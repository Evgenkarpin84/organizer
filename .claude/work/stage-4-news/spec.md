# Спецификация: этап 4 — сбор новостей и вкладка «Новости»

Статус: критерии приёмки заморожены 24.09.2026. Всё новое сверх них — в `BACKLOG.md`.

## 1. Цель и рамки

Цель: публикации по восьми темам владельца попадают в Supabase скриптом на ПК из
RSS/Atom-лент, а вкладка «Новости» вместо заглушки показывает их, сгруппированными по
темам, с фильтром по теме, отметкой «прочитано» и переходом на статью в браузер. Список
источников лежит файлом в репозитории, а не в `.env`, — источник добавляется и убирается
правкой одного файла.

Входит:
- скрипт `scripts/fetch-news.mjs`: загрузка лент по HTTP (`fetch` Node 22), разбор RSS 2.0
  и Atom, чистка HTML, обрезка текста, дедупликация, запись в Supabase под сервисным
  ключом; режимы `--check` (проверка конфигурации без сети) и `--dry-run` (загрузка без
  записи);
- конфигурация источников `scripts/news/sources.json`: тема, ключ, название, адрес ленты,
  флаг `enabled` и необязательный список ключевых слов;
- миграция `supabase/migrations/0004_news.sql`: таблицы `news_sources` и `news_items`,
  RLS, индексы, ограничения длины — как файл в репозитории;
- фронтенд: вкладка «Новости» (`/news`) вместо `StubScreen stage={4}` — группировка по
  темам, чипсы фильтра по теме, сегмент «Все / Непрочитанные», отметка «прочитано»,
  переход по ссылке в браузер, честная строка о том, что сбор идёт скриптом на ПК;
- чистые функции разбора ленты, дедупликации, обрезки, фильтрации и группировки — с
  тестами Vitest без сети;
- документация в `README.md` (раздел «Новости»), переменные в `.env.example`.

Не входит (этап 4b, см. раздел 12):
- **применение миграции к реальному проекту и первый запуск скрипта** — только файлы в
  репозитории, запуск делает пользователь отдельным шагом после приёмки;
- краткие сводки и выжимки моделью, оценка важности, объединение похожих новостей;
- утренний дайджест одним сообщением и push о новостях;
- полнотекстовая загрузка статей, картинки, превью-обложки;
- парсинг сайтов без RSS, Telegram-каналов, API маркетплейсов;
- поиск по новостям, «Показать ещё», избранное/«отложить», автоочистка старых записей;
- журнал запусков скриптов `job_runs` (пункт бэклога, общий для этапов 3–5).

Отступление от шаблона: критериев 12, а не 7. Этап неделим — скрипт без таблиц и экрана
не проверяется, экран без скрипта пуст, — а форма списка повторяет спеки этапов 0–1, 2 и 3
с пометками способа проверки.

## 2. Критерии приёмки

Проверка: `А` — автоматически (сборка, типы, тесты, линтер, поиск по файлам), `Р` —
вручную в браузере на ПК, `Б` — только на живых данных (применённая миграция `0004` +
реальные ленты в интернете).

- **AC1 (А). Гигиена сборки и секретов.** `npm run build`, `npm run typecheck`,
  `npm run lint`, `npm test` проходят без ошибок. Тесты не обращаются к сети и базе: в
  тестовых файлах нет `fetch(`, `createClient`, `requireSupabase` и `undici` — загрузка
  лент и запись проверяются только на строках-образцах и подставных объектах. В
  `.env.example` появились `NEWS_BACKFILL_DAYS` и `NEWS_MAX_PER_SOURCE` с пустыми
  значениями и без префикса `VITE_`; поиск по `src/**` не находит `SERVICE_ROLE`,
  `OWNER_USER_ID` и `sources.json`; собранный `dist` не содержит строки
  `SUPABASE_SERVICE_ROLE_KEY`.
- **AC2 (А). Конфигурация источников.** `scripts/news/sources.json` содержит ровно восемь
  тем (`ozon`, `cars`, `gadgets`, `print3d`, `cinema`, `ai`, `finance`, `world`) и не
  меньше двух включённых источников в каждой; у каждого источника есть `key`, `topic`,
  `title`, `feedUrl`, `enabled`, необязательный `include`. Чистая функция `parseSources`
  покрыта тестами: возвращает ошибки на русском с указанием ключа при повторе `key`,
  повторе `feedUrl`, неизвестной теме, пустом названии и адресе не на `http(s)`;
  отключённые (`enabled: false`) источники в выборку не попадают; при валидном файле
  возвращает список, отсортированный по порядку тем.
- **AC3 (А). Разбор лент.** `scripts/news/feed.mjs` покрыт тестами на строках-образцах:
  `parseFeed` разбирает RSS 2.0 (`item`, `title`, `link`, `guid`, `pubDate`,
  `description`) и Atom (`entry`, `id`, `link rel="alternate"`, `updated`/`published`,
  `summary`/`content`), разворачивает `CDATA` и базовые HTML-сущности, терпит отсутствие
  `guid` (берёт ссылку) и отсутствие даты (подставляет время загрузки); на обрезанном или
  не-XML ответе возвращает `{ items: [], error }` с текстом на русском и не выбрасывает
  исключение. `decodeBody(buffer, contentType)` читает `utf-8` и `windows-1251` (кодировка
  берётся из заголовка, а при его отсутствии — из XML-декларации).
- **AC4 (А). Чистка и пределы объёма.** Тестами покрыто: `stripHtml` удаляет теги вместе с
  содержимым `script`/`style`, разворачивает сущности и сжимает пробелы; `clampText`
  обрезает заголовок до 200 и краткое описание до 400 символов по границе слова с
  многоточием; `buildItemRow` возвращает ровно набор полей `user_id`, `source_id`, `topic`,
  `dedupe_key`, `guid`, `title`, `url`, `url_hash`, `summary`, `published_at`, `fetched_at`
  — ни поля с полным текстом статьи, ни поля с картинкой в строке нет.
- **AC5 (А). Дедупликация и отбор.** Тестами покрыто: `normalizeUrl` приводит схему и хост
  к нижнему регистру, убирает `utm_*`, `yclid`, `gclid`, `fbclid`, якорь и хвостовой слеш,
  сохраняя регистр пути; `dedupeKey` берёт `guid` источника, а без него — sha256
  нормализованной ссылки; `urlHash` — всегда sha256 нормализованной ссылки; `selectItems`
  отбрасывает публикации старше `NEWS_BACKFILL_DAYS` (по умолчанию 7 дней) и публикации из
  будущего дальше суток, оставляет не больше `NEWS_MAX_PER_SOURCE` (по умолчанию 30) самых
  свежих на источник и убирает повторы внутри одной ленты; `matchesKeywords` для источника
  со списком `include` оставляет публикацию, если слово из списка встречается в заголовке
  или описании без учёта регистра, и отбрасывает остальные.
- **AC6 (А). Миграция.** `supabase/migrations/0004_news.sql` создаёт таблицы
  `news_sources` и `news_items`, включает RLS и заводит по четыре политики (`select`,
  `insert`, `update`, `delete`) с условием `user_id = auth.uid()`; есть уникальные
  ограничения `news_sources (user_id, key)`, `news_items (user_id, dedupe_key)` и
  `news_items (user_id, url_hash)`, индексы `news_items (user_id, published_at desc)` и
  `news_items (user_id, topic, published_at desc)`, проверки длины `title` ≤ 300,
  `summary` ≤ 600, `url` ≤ 1000 и проверка допустимых значений `topic`. Скрипт идемпотентен
  (`create table if not exists`, `drop policy if exists`); схемы задач, напоминаний и почты
  не меняются.
- **AC7 (А). Запись в базу.** `scripts/news/store.mjs` работает через переданный клиент и
  покрыт тестами с подставным клиентом: при `dryRun: true` не вызывается ни один метод
  записи (`insert`, `upsert`, `update`) и возвращается сводка «сколько было бы добавлено»;
  при `dryRun: false` публикации уходят партиями по 50 через `upsert` с
  `onConflict: 'user_id,dedupe_key'` и `ignoreDuplicates: true`, а при нарушении второго
  уникального ключа (`user_id, url_hash`) партия не падает — строки перезаписываются по
  одной, конфликтные считаются как `skipped`; в каждой строке явно проставлен `user_id` из
  `OWNER_USER_ID`; состояние источника (`last_fetch_at`, `last_status`, `last_error`,
  `last_item_count`, `http_etag`, `http_last_modified`) обновляется после каждого
  источника; повторный запуск не затирает `read_at` у уже сохранённых публикаций.
- **AC8 (А). Экран «Новости».** `src/screens/NewsScreen.tsx` покрыт тестами компонента с
  подставленными данными: по умолчанию публикации сгруппированы по темам в фиксированном
  порядке с русскими заголовками («Ozon для продавца», «Китайские автомобили», «Смартфоны
  и гаджеты», «3D-печать», «Кино и сериалы», «ИИ и технологии», «Экономика и финансы»,
  «Мир и политика»), переключатель «Тема / Дата» меняет группировку на заголовки дней
  («Сегодня», «Вчера», «15 сентября»); чипсы «Все темы» + по чипу на тему фильтруют список
  и показывают число непрочитанных в теме; сегмент «Все / Непрочитанные» фильтрует набор;
  строка публикации содержит заголовок, название источника и время или дату, непрочитанная
  выделена; строка — ссылка `<a href target="_blank" rel="noopener noreferrer">` на
  исходный адрес; клик по ней ровно один раз вызывает отметку «прочитано»; пустые состояния
  «Новостей пока нет» и «Ничего не найдено» различаются текстом, у второго есть кнопка
  «Сбросить фильтры».
- **AC9 (А). Честный статус сбора.** Чистая функция `describeNewsSync(sources, unread, now,
  todayIso)` покрыта тестами и возвращает: при пустом списке источников — предупреждение
  «Сбор новостей ещё ни разу не запускался на компьютере…»; при последней загрузке
  6 часов назад и раньше — предупреждение с числом часов и пояснением, что новости
  собирает скрипт на ПК; при источнике с `last_error` — предупреждение с его названием;
  иначе — строку «N непрочитанных · обновлено сегодня в 12:40». На экране предупреждение
  показывается блоком `role="status"`, обычная строка — текстом над списком.
- **AC10 (А). Встраивание в приложение.** Нижняя навигация состоит ровно из пяти вкладок,
  заглушки `stage={4}` в `App.tsx` больше нет, маршрут `/news` работает в подкаталоге
  `/organizer/` (`HashRouter`, относительные пути сохранены). Новости грузит собственный
  провайдер `NewsProvider` + хук `useNews` (загрузка стартует при первом открытии вкладки);
  в `src/data/DataProvider.tsx` нет ни одного упоминания новостей, то есть экран «Сегодня»
  их не ждёт. Выборка ограничена: `NEWS_LIMIT = 200` и `.limit(` в `src/data/newsRepo.ts`.
  Выбранные тема, фильтр и группировка хранятся в `localStorage` (`news.topic`,
  `news.filter`, `news.group`) через существующий `useStoredState`, поэтому повторное
  монтирование экрана их не сбрасывает. Ошибки загрузки и записи показываются текстом на
  русском, уже загруженный список остаётся рабочим.
- **AC11 (Б). Живой запуск.** `npm run news -- --check` печатает таблицу источников по
  темам (не меньше 16 строк, 8 тем) и не делает ни одного сетевого вызова;
  `npm run news -- --dry-run` загружает ленты и сообщает по каждому источнику число новых
  публикаций, ничего не записав; `npm run news` записывает публикации, повторный запуск
  сразу после первого добавляет 0; при недоступной или переехавшей ленте скрипт пишет
  понятную ошибку с названием источника и кодом ответа, продолжает по остальным источникам
  и завершается кодом 1; отметка «прочитано» в приложении сохраняется после следующего
  запуска скрипта.
- **AC12 (А). Документация.** `README.md` содержит раздел «Новости»: как добавить источник
  (поля `scripts/news/sources.json`) и как его убрать (`enabled: false` или удаление
  записи), список тем с их ключами, таблицу переменных окружения, применение миграции
  `0004_news.sql`, ручной запуск (`npm run news`, `--check`, `--dry-run`, `--source=`,
  `--topic=`, `--limit=`), настройку расписания Windows одной командой `schtasks` (с
  созданием папки `logs`, путём к журналу и способом отключения) и подраздел «Что хранится
  в базе» с пределами 200/400 символов и явной оговоркой, что полный текст статей и
  картинки не сохраняются.

## 3. Модель данных

Миграция `supabase/migrations/0004_news.sql`.

`news_sources` — источник и его состояние загрузки:
- `id uuid pk default gen_random_uuid()`
- `user_id uuid not null default auth.uid() references auth.users (id) on delete cascade`
- `key text not null` — ключ из `sources.json`, уникален в паре `(user_id, key)`
- `topic text not null check (topic in ('ozon','cars','gadgets','print3d','cinema','ai','finance','world'))`
- `title text not null` — название издания в интерфейсе («4PDA»)
- `feed_url text not null`
- `enabled boolean not null default true`
- `http_etag text`, `http_last_modified text` — для условных запросов (`304 Not Modified`)
- `last_fetch_at timestamptz`, `last_status text check (last_status in ('ok','error'))`,
  `last_error text`, `last_item_count integer not null default 0`
- `created_at timestamptz not null default now()`

`news_items` — публикация:
- `id uuid pk default gen_random_uuid()`
- `user_id uuid not null default auth.uid() references auth.users (id) on delete cascade`
- `source_id uuid not null references public.news_sources (id) on delete cascade`
- `topic text not null` (то же ограничение, что у источника — фильтр по теме не делает
  join)
- `dedupe_key text not null`, уникально в паре `(user_id, dedupe_key)`
- `url_hash text not null`, уникально в паре `(user_id, url_hash)`
- `guid text`
- `title text not null check (char_length(title) <= 300)`
- `url text not null check (char_length(url) <= 1000)`
- `summary text check (summary is null or char_length(summary) <= 600)`
- `published_at timestamptz not null` — по нему сортировка
- `fetched_at timestamptz not null default now()`
- `read_at timestamptz`
- `created_at timestamptz not null default now()`

Индексы: `news_items (user_id, published_at desc)`,
`news_items (user_id, topic, published_at desc)`, `news_sources (user_id, key)`.

RLS включена на обеих таблицах, по четыре политики с `user_id = auth.uid()`. Скрипт
работает под `service_role` и RLS обходит, поэтому `user_id` в каждой строке подставляется
явно из `OWNER_USER_ID`.

Типы фронтенда в `src/lib/types.ts`: `NewsSource` (`id`, `key`, `topic`, `title`,
`enabled`, `lastFetchAt`, `lastStatus`, `lastError`) и `NewsItem` (`id`, `sourceId`,
`topic`, `title`, `url`, `summary`, `publishedAt`, `readAt`).

## 4. Конфигурация источников

`scripts/news/sources.json` — единственное место, где заданы ленты. Формат:

```json
{
  "sources": [
    {
      "key": "epepper",
      "topic": "ozon",
      "title": "E-pepper",
      "feedUrl": "https://e-pepper.ru/rss",
      "enabled": true,
      "include": ["ozon", "озон", "маркетплейс", "селлер", "продавц"]
    }
  ]
}
```

`include` — необязательный список слов: если он задан, публикация берётся только при
совпадении в заголовке или описании (совпадение по подстроке, без учёта регистра, поэтому
«продавц» покрывает «продавцов» и «продавцам»). Он нужен там, где своей узкой ленты не
существует: «Ozon для продавца» и «Китайские автомобили» живут внутри общих лент об
e-commerce и об автомобилях.

| `world` | Lenta.ru: Мир | `https://lenta.ru/rss/news/world` | второй взгляд на ту же повестку; дубли снимает `url_hash` |

Две ленты на тему — сознательное решение: одна умершая лента не должна оставлять тему
пустой, а дублирующиеся публикации отсекает дедупликация по нормализованной ссылке.

## 5. Устройство скрипта

```
scripts/fetch-news.mjs      точка входа: аргументы, .env, цикл по источникам, запись
scripts/news/sources.json   конфигурация источников (в репозитории, не в .env)
scripts/news/config.mjs     parseSources, parseArgs, readOptions, TOPICS — чистые
scripts/news/feed.mjs       parseFeed, decodeBody, stripHtml, clampText, normalizeUrl,
                            dedupeKey, urlHash, selectItems, matchesKeywords,
                            buildItemRow — чистые
scripts/news/store.mjs      loadSources, upsertItems, saveSourceState, saveSourceError —
                            работа через переданный клиент, с флагом dryRun
scripts/news/*.test.mjs     тесты Vitest с явным import { describe, expect, it } from 'vitest'
```

Ход работы:
1. Разбор аргументов: `--check`, `--dry-run`, `--source=<key>`, `--topic=<key>`,
   `--limit=<N>`, `--verbose`.
2. Чтение `sources.json` (`node:fs`) и `parseSources`: при ошибках печатается список
   проблем и код выхода 1.
3. Режим `--check` заканчивается здесь: таблица «тема — ключ — название — адрес ленты»,
   счётчик источников и тем, ни одного сетевого вызова.
4. Чтение `.env` через `process.loadEnvFile()` в `try/catch`; нет файла — сообщение
   «Создайте .env из .env.example» и код 1. Клиент Supabase на `SUPABASE_URL` +
   `SUPABASE_SERVICE_ROLE_KEY`, `persistSession: false`.
5. Строки источников читаются или создаются (`news_sources` по `(user_id, key)`); название
   и адрес ленты синхронизируются с файлом конфигурации, если они изменились.
6. По каждому источнику: `fetch` с `signal: AbortSignal.timeout(15000)`, заголовками
   `User-Agent: organizer-news/1.0`, `Accept: application/rss+xml, application/atom+xml,
   application/xml;q=0.9, */*;q=0.8` и условными `If-None-Match` / `If-Modified-Since` из
   сохранённого состояния. Ответ `304` — «без изменений», 0 публикаций. Тело читается не
   больше 2 МБ, декодируется `decodeBody`.
7. `parseFeed` → `matchesKeywords` → `selectItems` (окно `NEWS_BACKFILL_DAYS`, предел
   `NEWS_MAX_PER_SOURCE`) → `buildItemRow`.
8. Партии по 50 строк уходят `upsert` с `ignoreDuplicates: true`; затем сохраняется
   состояние источника вместе с новыми `ETag`/`Last-Modified`. В `--dry-run` вместо записи
   считается количество.
9. Итог: по каждому источнику «название: получено N, добавлено M» и общая сводка по темам;
   ошибка одного источника не срывает остальные, но итоговый код выхода 1. Сетевые ошибки
   переводятся в понятный текст: лента не найдена (404), сервер недоступен, таймаут, ответ
   не XML.

## 6. Расписание Windows

Скрипт вызывается `npm run news`, журнал — `logs\news.log` (папка `logs/` уже в
`.gitignore`). Регистрация задания раз в 2 часа:

```powershell
schtasks /create /tn "Органайзер: новости" /sc minute /mo 120 /f `
  /tr "cmd /c cd /d C:\newIDEA && if not exist logs md logs && npm run news >> logs\news.log 2>&1"
```

Разовый запуск — `schtasks /run /tn "Органайзер: новости"`, отключение —
`schtasks /delete /tn "Органайзер: новости" /f`. Каждые 2 часа, а не 30 минут, как почта:
новостная лента не требует минутной свежести, а частые запросы к 17 лентам — лишняя
нагрузка. Задание работает только при включённом ПК — то же осознанное ограничение, что в
этапе 3.

## 8. Стек и зависимости

Новых зависимостей нет:
- **HTTP** — встроенный `fetch` Node 22 с `AbortSignal.timeout`; `node-fetch`/`axios` не
  нужны.
- **XML** — своя чистая функция `parseFeed` (RSS 2.0 + Atom, только нужные поля). Отклонены
  `rss-parser`, `feedparser` и `fast-xml-parser`: полный разбор XML тут не требуется, а
  чистую функцию всё равно надо покрывать тестами — и она же гарантирует, что в базу не
  попадут лишние поля.
- **Кодировки** — `TextDecoder('windows-1251')` из стандартной библиотеки (`iconv-lite` не
  нужен).
- **`.env`** — `process.loadEnvFile()`, как в этапе 3.
- **Supabase** — уже подключённый `@supabase/supabase-js`.
- **Тесты** — существующий Vitest; `scripts/**/*.test.mjs` уже в `test.include`
  (`vite.config.ts` менять не нужно).

Фронтенд новых пакетов не получает. Новые переменные окружения (без префикса `VITE_`):

| Переменная | Значение |
|---|---|
| `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `OWNER_USER_ID` | уже есть, используются как есть |
| `NEWS_BACKFILL_DAYS` | окно свежести публикаций, по умолчанию 7 |
| `NEWS_MAX_PER_SOURCE` | предел публикаций с одного источника за запуск, по умолчанию 30 |

Новый npm-скрипт: `"news": "node scripts/fetch-news.mjs"`.

## 11. Принятые допущения

1. Темы фиксированы восемью ключами из раздела 4; ключ темы хранится строкой в базе, а
   русское название живёт в `src/lib/news.ts` и в `scripts/news/config.mjs`. Добавление
   новой темы — правка обоих мест, это описано в README.
2. У Ozon Seller нет публичной RSS-ленты, поэтому тема «Ozon для продавца» собирается из
   отраслевых изданий с фильтром `include`. Часть объявлений площадки в органайзер не
   попадёт — официальный кабинет продавца остаётся основным источником правил.
3. Тема «Китайские автомобили» тоже собирается фильтром по списку брендов: узкой ленты
   только про китайские марки в РФ нет. Новый бренд добавляется словом в `include`.
4. Адреса лент взяты по стандартным для этих изданий путям и проверяются первым живым
   запуском (`npm run news -- --dry-run`). Если лента переехала, скрипт пишет понятную
   ошибку с названием источника, остальные темы продолжают наполняться, а адрес правится в
   `sources.json` — это ожидаемое обслуживание, а не дефект.
5. На тему берётся не меньше двух лент: одна замолчавшая лента не должна оставлять тему
   пустой. Пересечения снимает дедупликация по нормализованной ссылке.
6. Хранится только то, что отдаёт лента: заголовок (≤ 200 символов), ссылка, краткое
   описание (≤ 400 символов), дата, тема, источник. Полный текст статей и картинки не
   загружаются — читать статью пользователь идёт по ссылке.
7. Публикация без даты в ленте получает время загрузки: иначе она навсегда выпала бы из
   окна свежести.
8. Окно свежести — 7 дней, предел 30 публикаций на источник за запуск. Архив лент не
   выкачивается.
9. Дедупликация двумя ключами: `(user_id, dedupe_key)` (guid, а без него — хэш ссылки) и
   `(user_id, url_hash)` (хэш нормализованной ссылки). Второй ключ ловит одну и ту же
   статью, пришедшую из разных лент или с новым guid; конфликт по нему не роняет партию, а
   считается пропуском.
10. Условные запросы (`ETag`/`Last-Modified`) включены: при `304` источник считается
    успешно проверенным без публикаций.
11. `user_id` подставляется скриптом из `OWNER_USER_ID`: под сервисным ключом `auth.uid()`
    пуст.
12. Список на экране — последние 200 публикаций; «Показать ещё» и автоочистка старых
    записей — пункты бэклога.
13. Отметка «прочитано» ставится в момент перехода по ссылке (и только так); отдельной
    кнопки «прочитано» и «прочитать всё» на этом этапе нет.
14. Статья открывается во внешнем браузере (`target="_blank"`), внутреннего экрана
    публикации нет: полного текста в базе всё равно нет, а `/news/:id` был бы пустой
    страницей.
15. Порог «давно не обновлялось» — 6 часов при расписании раз в 2 часа (у почты 3 часа при
    30 минутах): ночью ПК выключен, и утреннее предупреждение раньше — шум.
16. Новых зависимостей нет: `fetch`, `TextDecoder` и своя чистая функция разбора XML.
17. Скрипт запускается только вручную пользователем после приёмки; миграцию `0004` и
    задание Windows пользователь применяет сам.
18. Своего журнала запусков (`job_runs`) скрипт не ведёт: вывод идёт в `logs\news.log`,
    единый журнал для всех скриптов — пункт бэклога (общий для этапов 3–5).
