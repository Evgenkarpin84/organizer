# Дизайн: вкладка «Новости» (этап 4)

Объём — чуть больше одной страницы: этап добавляет один экран, но с тремя рядами
управления, двумя группировками и восемью темами. Блоки читаются независимо. Палитра,
типографика, `FOCUS_RING`, `Section`, `EmptyState`/`ErrorState`/`SkeletonList`, правила
доступности — из `stage-0-1-tasks/design.md`. Новых токенов и новых иконок нет
(`news` в `Icon.tsx` уже есть). Приёмы ряда управления, статуса сбора и пустых состояний —
те же, что в `stage-3-mail/design.md`.

## Основной сценарий

1. Вкладка «Новости» → список публикаций, сгруппированный по темам, непрочитанные выделены.
2. (необязательно) тап по чипу темы или по сегменту «Непрочитанные».
3. Тап по строке → статья открывается в браузере, строка сразу становится прочитанной.
4. Возврат в приложение (аппаратная «Назад» / переключение приложений) → список на том же
   месте, публикация уже без синей точки.

Основной сценарий — **1 касание** до чтения статьи, 2 с фильтром по теме.

## Экран «Новости» (`src/screens/NewsScreen.tsx`)

Заголовок «Новости» уже есть в `TITLES` (`AppShell`), шапка не меняется. Экран рендерится
внутри `<Route element={<AppShell />}>` вместо `StubScreen stage={4}`. Компонент делится на
`NewsView` (чистый, принимает данные пропсами — его и покрывают тесты AC8) и `NewsScreen`
(берёт данные из `useNews`) — ровно как `MailView` / `MailScreen`.

### Ряд 1 — набор публикаций

Точная копия `ViewToggle` из `MailView`, две кнопки вместо трёх:

```tsx
<div role="tablist" aria-label="Фильтр новостей" className="mb-2 flex rounded-xl bg-slate-200 p-1">
  {([['all','Все'],['unread','Непрочитанные']] as [NewsFilter, string][]).map(([key, label]) => (
    <button key={key} role="tab" type="button" aria-selected={filter === key} onClick={() => setFilter(key)}

      <span className="truncate">{label}</span>
      {key === 'unread' && unread > 0 ? (

```

### Ряд 2 — фильтр по теме (восемь тем компактно)

Лента чипсов по образцу `ListFilterChips` / ряда ящиков в `MailView`:
`-mx-4 flex gap-2 overflow-x-auto px-4 pb-2 [scrollbar-width:none]`, чип
`inline-flex h-9 shrink-0 items-center gap-2 rounded-full border px-3 text-sm`, выбранный —
`border-transparent bg-slate-900 text-white`, невыбранный — `border-slate-300 bg-white text-slate-700`.
Первый чип «Все темы», далее восемь тем **в фиксированном порядке** (позиция темы не прыгает).

Чтобы восемь чипсов были обозримы на 360 px, у темы два названия в `src/lib/news.ts`:

| Ключ | Полное (`topicTitle`, заголовок `Section`) | Короткое (`topicShortTitle`, чип) | Цвет |
|---|---|---|---|
| `ozon` | Ozon для продавца | Ozon | slate |
| `cars` | Китайские автомобили | Авто | blue |
| `gadgets` | Смартфоны и гаджеты | Гаджеты | green |
| `print3d` | 3D-печать | 3D-печать | amber |
| `cinema` | Кино и сериалы | Кино | rose |
| `ai` | ИИ и технологии | ИИ | violet |
| `finance` | Экономика и финансы | Экономика | slate |
| `world` | Мир и политика | Мир | blue |

Цвет — `LIST_COLORS[topicColor(topic)]`, где
`topicColor(topic) = LIST_COLOR_KEYS[NEWS_TOPICS.indexOf(topic) % LIST_COLOR_KEYS.length]` —
тот же приём, что `accountColor(index)` у ящиков, новых токенов нет. Палитра из шести цветов
на восемь тем даёт два повтора (`ozon`/`finance`, `cars`/`world`) — они разнесены на шесть
позиций, соседние темы всегда разного цвета, и цвет нигде не единственный носитель смысла:
рядом с точкой всегда стоит название темы.

```tsx
<button type="button" onClick={() => setTopic(topic)}
  aria-label={`Тема: ${topicTitle(topic)}${topicUnread ? `, непрочитанных ${topicUnread}` : ''}`}
  className={`inline-flex h-9 shrink-0 items-center gap-2 rounded-full border px-3 text-sm ${FOCUS_RING} ${…}`}>
  <span className={`h-2 w-2 rounded-full ${LIST_COLORS[topicColor(topic)].dot}`} aria-hidden="true" />
  {topicShortTitle(topic)}
  {topicUnread > 0 ? <span className={`text-xs ${selected ? 'text-slate-300' : 'text-slate-500'}`}>{topicUnread}</span> : null}
</button>
```

Чипсы рендерятся для всех восьми тем всегда, даже если публикаций по теме нет: список тем —
константа, а не производная от данных, и исчезающий чип выглядел бы как сбой. У темы без
публикаций подпись `text-slate-400`, тап ведёт в состояние «Ничего не найдено» со сбросом.

### Ряд 3 — статус сбора и группировка

Разметка ряда — как в `MailView` (ряд 3): слева `min-w-0 flex-1 text-xs text-slate-500`,
справа `role="group" aria-label="Группировка"` с двумя кнопками
`h-9 rounded-md px-3 text-xs font-medium` (`aria-pressed`, активная —
`bg-white text-slate-900 shadow-sm`): **«Тема»** (по умолчанию) и **«Дата»**.

### Отставание сбора — `describeNewsSync(sources, unread, now, todayIso)`

Чистая функция в `src/lib/news.ts`, возвращает `{ tone: 'ok' | 'warn'; text: string }`.
Порог — **6 часов** при расписании раз в 2 часа. Источник — `max(lastFetchAt)` и первый
`lastError` по `news_sources`.

| Случай | `tone` | Что видно |
|---|---|---|
| Свежо (< 6 ч) | `ok` | строка `text-xs text-slate-500`: «12 непрочитанных · обновлено сегодня в 12:40» |
| Давно (≥ 6 ч) | `warn` | «Новости не обновлялись 8 часов. Новости собирает скрипт на компьютере — при выключенном ПК лента не пополняется.» |
| `lastFetchAt` пуст у всех источников | `warn` | «Сбор новостей ещё ни разу не запускался на компьютере.» |
| У источника заполнен `lastError` | `warn` | «Источник «4PDA» не обновляется: лента не найдена (404). Остальные источники в порядке.» |
| Источников в базе нет | `warn` | «Источники ещё не собирались. Запустите сбор новостей на компьютере: npm run news» |

`warn` — блок `role="status" className="mb-2 rounded-lg bg-amber-100 px-3 py-2 text-xs text-amber-900"`
над рядом 3 (порядок и классы как у `MailView`); `ok` — текст в ряду 3. Ошибка одного
источника не красит экран в красный: список работает, остальные 16 лент наполняются — это
частичные данные, а не отказ. Название источника в тексте обязательно: только по нему
понятно, какую строку `sources.json` править. Текст ошибки — как сохранил скрипт.

Строка «N непрочитанных · обновлено сегодня в 12:40» — **главная цифра экрана**: она стоит
выше первой публикации и продублирована бейджем в сегменте «Непрочитанные». Единица и
период названы словами («непрочитанных», «сегодня в 12:40»), а не иконкой.

### Список и группировка

- **По теме** (по умолчанию): `Section` с полным русским названием темы в фиксированном
  порядке `NEWS_TOPICS`; пустые темы пропускаются (в отличие от чипсов — пустой раздел
  списка это мусор, а не ориентир). `count` = число публикаций в группе.
- **По дате**: `Section` «Сегодня», «Вчера», далее «15 сентября» (`formatNewsGroupTitle` —
  тот же `dayTitle`, что в `lib/mail.ts`), группы от свежих к старым.
- Внутри группы всегда `publishedAt desc` — строгая хронология. Непрочитанные наверх **не
  всплывают**: иначе после возврата из браузера строка прыгает по списку. Сортировка по
  умолчанию «свежее сверху» — единственная осмысленная для новостной ленты.
- Разделение прочитанных и непрочитанных делает вид строки (синяя точка, `font-semibold`,
  фон) плюс один тап по сегменту «Непрочитанные». Дублирующей секции «Непрочитанные» над
  группами нет — одна публикация не должна встречаться в списке дважды.

### Строка публикации (`src/components/NewsItem.tsx`)

```tsx
<li className="mb-2">
  <a href={item.url} target="_blank" rel="noopener noreferrer" onClick={() => onOpen(item)}
    className={`flex min-h-[4.5rem] w-full items-start gap-2.5 rounded-xl border border-slate-200 px-3 py-2.5 text-left active:bg-slate-50 ${FOCUS_RING} ${
      unread ? 'bg-white' : 'bg-white/70'}`}>
    {unread ? (
      <>
        <span className="mt-2 h-2 w-2 shrink-0 rounded-full bg-blue-600" aria-hidden="true" />
        <span className="sr-only">Не прочитано.</span>
      </>
    ) : (
      <span className="mt-2 h-2 w-2 shrink-0" aria-hidden="true" />
    )}

    <span className="min-w-0 flex-1">
      <span className={`line-clamp-2 text-[15px] leading-snug [overflow-wrap:anywhere] ${
        unread ? 'font-semibold text-slate-900' : 'text-slate-700'}`}>{item.title}</span>

      {item.summary ? (
        <span className="mt-0.5 line-clamp-2 text-xs text-slate-500 [overflow-wrap:anywhere]">{item.summary}</span>
      ) : null}

      <span className="mt-1 flex flex-wrap items-center gap-x-2 gap-y-1 text-xs text-slate-500">
        {hideTopicChip ? null : (
          <span className={`inline-flex items-center rounded-full px-2 py-0.5 ${LIST_COLORS[topicColor(item.topic)].chip}`}>
            {topicShortTitle(item.topic)}
          </span>
        )}
        <span className="min-w-0 truncate">{source?.title ?? 'Источник неизвестен'}</span>
        <span className="shrink-0">{formatNewsDate(item.publishedAt, todayIso)}</span>
      </span>
      <span className="sr-only">Откроется в браузере.</span>
    </span>
  </a>
</li>
```

- `hideTopicChip = grouping === 'topic' || topic !== null` — правило `hideAccountChip` из
  `MailItem`: не дублировать заголовок группы и выбранный фильтр.
- `formatNewsDate`: сегодня — «12:40», вчера — «Вчера», в этом году — «15 сент.», иначе
  «15 сент. 2025» (точная копия `formatMailDate`). Время остаётся и при группировке по дате:
  внутри дня оно единственный ориентир свежести.
- Заголовок — **две строки** `line-clamp-2`, а не `truncate`: в почте есть экран письма, где
  тему видно целиком, здесь экрана нет — заголовок и есть содержание. Описание тоже
  `line-clamp-2`: четыре строки текста на строку списка — предел, дальше список не
  просматривается. Полностью заголовок и описание доступны в самой статье.
- Порядок в мета-строке: тема → источник → время. Источник важнее времени (доверие к
  публикации), время стоит последним и `shrink-0`, поэтому при длинном названии источника
  урезается название, а не дата.
- Действий внутри строки нет: вся строка — одна ссылка, промахнуться некуда. Отдельной
  кнопки «прочитано» нет (допущение 13 спеки).

### Переход по ссылке и отметка «прочитано»

`<a target="_blank" rel="noopener noreferrer">` — на Android в PWA (`display: standalone`)
ссылка открывается во внешнем браузере (Custom Tab), на ПК — в новой вкладке. Приложение
остаётся смонтированным, возврат аппаратной «Назад» или переключением приложений возвращает
список с сохранённой прокруткой — своего перехода делать не нужно.

`onOpen` вызывает `markRead(item)` **оптимистично**: точка гаснет мгновенно, до ответа сети.
`markRead` идемпотентен (`if (item.readAt) return`), поэтому повторный тап по прочитанной
строке запроса не делает — это же даёт AC8 «ровно один вызов». `preventDefault` не
вызывается никогда: отметка не должна мешать открытию статьи.

Отдельного экрана публикации (`/news/:id`) нет: в базе хранятся только заголовок, описание до
400 символов и ссылка (допущение 6 спеки) — экран показал бы ровно то, что уже видно в
строке, добавив лишний шаг до статьи. Читать всё равно идти в браузер, значит из списка туда
надо попадать за одно касание.

### Состояния экрана

| Состояние | Что видно | Действие пользователя |
|---|---|---|
| Загрузка | Ряды управления отрисованы, вместо списка `SkeletonList count={5}` | ждать |
| Норма | Статус сбора + группы со строками публикаций | тап по строке |
| Пусто, источников в базе нет | `EmptyState icon="news"` «Новостей пока нет», hint «Запустите сбор новостей на компьютере: npm run news» | запустить скрипт на ПК |
| Пусто, источники есть | `EmptyState icon="news"` «Новостей пока нет», hint «Последний сбор: сегодня в 12:40. Новых публикаций не было.» | ждать |
| Пусто после фильтра | `EmptyState icon="news"` «Ничего не найдено», hint «Нет публикаций с такими фильтрами», `action` — кнопка «Сбросить фильтры» (`h-11 rounded-lg border border-slate-300 bg-white px-4 text-sm font-medium`) | сброс одним тапом |
| Ошибка загрузки, публикаций нет | только `ErrorState` «Не удалось загрузить новости. Попробуйте ещё раз.» + «Повторить» | «Повторить» |
| Ошибка обновления, публикации уже есть | `ErrorState` над рядами, список из состояния хука остаётся рабочим и кликабельным | «Повторить» |
| Ошибка отметки «прочитано» | Точка возвращается (откат), под рядами `<p role="status" className="mb-2 rounded-lg bg-rose-50 px-3 py-2 text-xs text-rose-700">` «Не удалось отметить публикацию прочитанной.» Статья при этом открылась | повторный тап по строке |
| Частичные данные (источник с `lastError`) | Список полный, сверху amber-блок про конкретный источник | править `sources.json` на ПК |
| Нет сети | `OfflineBanner` из `AppShell`; список показывается как есть, ссылки ведут в браузер (там и покажется ошибка сети) | — |

Два разных пустых текста обязательны (AC8): «Новостей пока нет» требует запустить скрипт,
«Ничего не найдено» — сбросить фильтры. Смешивать их нельзя: действия разные.

### Хранение выбора

`localStorage` через существующий `useStoredState`: `news.topic`, `news.filter`, `news.group`.
Тема хранится ключом (`'ai'`), а не индексом; неизвестный ключ (тема переименована) молча
превращается в «Все темы».

## Доступность и удобство на телефоне

- Строка публикации — ссылка на всю ширину `min-h-[4.5rem]`, цель нажатия заметно больше
  48dp, между строками `mb-2`. Мелких целей внутри строки нет вообще.
- Чипсы тем `h-9 px-3` в ленте с `gap-2` и `pb-2` — как принято в `ListFilterChips`; сегменты
  `h-10` внутри контейнера с `p-1`.
- Одной рукой: управления ровно три ряда и они нужны редко, основная площадь — список, по
  которому идёт прокрутка и тап; лента чипсов прокручивается тем же большим пальцем. Кнопок
  в шапке экран не добавляет.
- Крупный системный шрифт: у строки `min-h-*`, а не `h-*`; мета-строка `flex-wrap`; в
  сегментах подписи `truncate`, бейдж `shrink-0`; заголовки чипсов короткие, поэтому ряд не
  разваливается. Горизонтальной прокрутки контента нет ни при каком заголовке —
  `[overflow-wrap:anywhere]` ломает длинные слова и склеенные ссылки.
- Контраст: `text-slate-900`/`text-slate-700` для заголовков, `text-slate-500` для описания и
  меты на белом, `bg-amber-100 text-amber-900` для отставания сбора, `text-rose-700` на
  `bg-rose-50` для ошибок — палитра этапа 0–1. `text-slate-400` — только у пустых тем в
  ленте чипсов.
- Непрочитанность не держится на цвете: точка + `font-semibold` + фон `bg-white` против
  `bg-white/70` + `sr-only` «Не прочитано» в начале строки.
- Порядок фокуса = порядок DOM: сегмент «Все/Непрочитанные» → чипсы тем → группировка →
  строки публикаций → нижняя навигация. Внутри строки один фокусируемый элемент — ссылка.
- Заголовки: `h1` «Новости» в `AppShell`, `h2` — заголовки групп (`Section`). Пропусков нет.
- Скринридер: у чипа темы `aria-label` с полным названием и числом непрочитанных (короткая
  подпись «ИИ» вне контекста непонятна); точка цвета `aria-hidden`; у ссылки в конце
  `sr-only` «Откроется в браузере» — предупреждение о смене контекста.
- Безопасность внешних ссылок: `target="_blank"` **всегда** с `rel="noopener noreferrer"` —
  чужая страница не получает `window.opener` и адрес органайзера в `Referer`. `item.summary`
  выводится текстом (`{item.summary}`), `dangerouslySetInnerHTML` не используется: HTML уже
  вычищен скриптом, но доверять чужой ленте на фронтенде незачем. Схема `url` не проверяется
  на клиенте — в базе только `http(s)` (AC2 + проверка в `normalizeUrl`).
- `FOCUS_RING` на всех интерактивных элементах; тексты ошибок без кодов, технические детали —
  только `console.error`.

## Что осознанно НЕ делаем

- Отдельный экран публикации `/news/:id` — полного текста в базе нет, экран был бы пустым.
- Кнопка «Прочитано» в строке и «Прочитать всё в теме» — вне AC, кандидаты бэклога.
- Поиск и фильтр по источнику — вне AC (разд. 13 спеки).
- «Показать ещё» / бесконечная прокрутка — список ограничен 200 публикациями (допущение 12).
- Картинки-превью и обложки — не хранятся принципиально (допущение 6).
- Кнопка «Собрать новости сейчас» — фронтенд не может запустить скрипт на ПК; вместо неё
  честная строка статуса.
- Экран «Источники» с состоянием лент и переключателем `enabled` — 17 источников правятся
  файлом в репозитории, состояние показывает amber-строка.
- Свайпы «прочитано/скрыть» по строке — правило этапа 0–1: случайные жесты.
- Скрытие прочитанных из списка по умолчанию — ломает «вернулся и нашёл то же место»;
  вместо него сегмент «Непрочитанные» одним тапом.
- Многоместный выбор тем (несколько чипсов сразу) — одиночный выбор, как у списков задач и
  ящиков почты; комбинации фильтров на восьми темах никто не удержит в голове.
- Счётчик «сколько всего публикаций за период» и сводка по темам — это отчёт, его нет в AC.
- Тёмная тема, анимации переходов, офлайн-кэш ленты — бэклог.

## Решения дизайнера (спорные места)

1. **Группировка по теме — по умолчанию**, не по дате: тема — то, зачем владелец открывает
   вкладку («что по Ozon»), а дата в новостной ленте и так почти всегда «сегодня».
2. **У темы два названия**: полное в заголовке `Section` и `aria-label`, короткое в чипе и
   в чипе строки. Иначе восемь чипсов превращаются в ленту длиной в три экрана.
3. **Цвета тем — `LIST_COLOR_KEYS` по индексу**, с двумя повторами на восемь тем. Новую
   палитру ради различения `ozon` и `finance` заводить не стоит: название темы всегда рядом,
   цвет — только ускоритель узнавания.
4. **Чипсы рендерятся для всех восьми тем, включая пустые**, а пустые группы списка —
   пропускаются. Фильтр — постоянная карта тем, список — только то, что есть.
5. **Порог «давно не обновлялось» — 6 часов** (у почты 3 при расписании 30 минут): раз в
   2 часа + выключенный ПК ночью, раньше — шум каждое утро.
6. **Ошибка источника — amber, а не rose.** Одна упавшая лента из 17 — частичные данные;
   красный зарезервирован за отказом загрузки самого экрана.
7. **Непрочитанные не всплывают наверх группы** — после возврата из браузера строка не должна
   менять позицию, иначе теряется место чтения.
8. **Отметка «прочитано» ставится только переходом по ссылке** и не откатывает открытие
   статьи: даже если запись в базу не удалась, статья уже открыта — сообщаем и всё.
9. **Заголовок в две строки, описание в две** — четыре строки текста на публикацию: меньше
   не даёт понять, о чём новость (экрана-то нет), больше ломает просмотр списка.
10. **`NewsSyncStatus` — свой тип в `src/lib/news.ts`**, а не импорт `SyncStatus` из
    `lib/mail.ts`: два поля дешевле связывать заново, чем сцеплять модули почты и новостей.
11. **Строка публикации — `<a>`, а не `<button>`** (в отличие от `MailItem`): нужны
    «открыть в новой вкладке» из контекстного меню, долгое нажатие «скопировать ссылку» и
    правильная озвучка «ссылка» скринридером.
12. **Сегмент «Все / Непрочитанные» — две кнопки, без «Прочитанные»**: третий набор никому
    не нужен, а ряд от него становится теснее.
