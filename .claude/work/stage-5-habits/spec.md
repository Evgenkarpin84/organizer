# Спецификация: этап 5 — привычки и чеклисты

Статус: критерии приёмки заморожены 24.09.2026. Всё новое сверх них — в `BACKLOG.md`.

## 1. Цель и рамки

Цель: закрыть последний модуль органайзера. Привычка — регулярное действие с гибкой целью
(каждый день, N раз в неделю, в выбранные дни недели), которое отмечается галочкой за день;
видно серию дней подряд и процент за последние 7 дней. Чеклист — многоразовый шаблон:
проходится по пунктам, показывает прогресс «5 из 12», завершается и запускается заново с
нуля. Вкладка «Привычки» перестаёт быть заглушкой, а экран «Сегодня» получает компактную
строку отметок за сегодня, как на исходном макете.

Входит:
- привычки: создание, изменение, архивирование и возврат из архива, удаление; цель
  «каждый день» / «N раз в неделю» / «в выбранные дни недели»; отметка выполнения за
  локальную дату и снятие отметки (в том числе за прошедшие дни сетки);
- показатели привычки: серия подряд, процент за последние 7 дней, сетка последних 7 дней;
- чеклисты: шаблон со списком пунктов, прохождение с отметкой пунктов, прогресс «5 из 12»,
  «Завершить» и «Начать заново»;
- вкладка «Привычки» (`/habits`) вместо `StubScreen stage={5}`: привычки и чеклисты двумя
  секциями на одном экране;
- блок привычек на экране «Сегодня»: только привычки, запланированные на сегодня;
- миграция `supabase/migrations/0005_habits.sql` (таблицы, ограничения, индексы, RLS) —
  как файл в репозитории;
- чистые функции расписания, серий, процентов и прогресса чеклиста с тестами Vitest;
- раздел «Привычки и чеклисты» в `README.md`.

Не входит (см. раздел 11):
- **применение миграции к реальному проекту** — только файлы в репозитории, `0005` применяет
  пользователь отдельным шагом после приёмки;
- push-напоминания о привычках (механизм этапа 2 есть, связка с привычками — отдельная
  задача, зависит от пункта бэклога «Единая очередь уведомлений»);
- генерация чеклиста моделью по описанию («командировка на 3 дня»);
- статистика за месяц, графики, календарь-месяц, экспорт;
- история прохождений чеклиста (обоснование — раздел 5), общие чеклисты на нескольких
  человек, готовые шаблоны из интернета;
- перетаскивание для смены порядка привычек и пунктов (порядок — только добавление в конец);
- офлайн-отметки: как и в этапах 1–4, запись требует сети.

Отступление от шаблона: критериев 12, а не 7. Этап неделим — привычки и чеклисты живут на
одной вкладке и в одной миграции, а блок на «Сегодня» без привычек не проверяется. Форма
списка повторяет спеки этапов 0–1, 2, 3 и 4 с пометками способа проверки.

## 2. Критерии приёмки

Проверка: `А` — автоматически (сборка, типы, тесты, линтер, поиск по файлам), `Р` — вручную
в браузере на ПК, `Б` — только на живых данных (применённая миграция `0005`).

  `npm test` проходят без ошибок. Новых зависимостей в `package.json` нет, новых переменных
  окружения нет. Тесты привычек не обращаются к сети и базе: в них нет `createClient`,
  `requireSupabase` и `fetch(` — расчёты проверяются на массивах-образцах, экраны на
  подставленных данных и функциях-шпионах.

  `habit_entries`, `checklists`, `checklist_items`; на всех четырёх включена RLS и заведено
  по четыре политики (`select`, `insert`, `update`, `delete`) с условием `user_id =
  auth.uid()`. Есть уникальное ограничение `habit_entries (habit_id, done_on)` и индексы
  `habits (user_id, position)`, `habit_entries (user_id, done_on)`,
  `checklists (user_id, position)`, `checklist_items (checklist_id, position)`. Есть
  проверки `goal_type in ('daily','times_per_week','weekdays')`, `goal_times between 1 and
  7`, `goal_weekdays <@ array[1,2,3,4,5,6,7]`, длина `habits.title` ≤ 80,
  `checklists.title` ≤ 80, `checklist_items.text` ≤ 120. Триггер `public.set_updated_at`

- **AC3 (А). Расписание привычки.** Чистые функции в `src/lib/habits.ts` покрыты тестами:
  `isScheduledOn(habit, iso)` для цели `daily` возвращает `true` на любой дате, для
  `weekdays` — только для дней из `goalWeekdays` (1 — понедельник, 7 — воскресенье), для
  `times_per_week` — `true` на любой дате (гибкая цель не привязана к дню);
  `describeGoal(habit)` даёт «каждый день», «3 раза в неделю», «по пн, ср, пт» (дни всегда
  по возрастанию).
- **AC4 (А). Серия.** `habitStreak(habit, doneDates, todayIso)` покрыта тестами и
  возвращает `{ unit, value, atWindowEdge }`: для `daily` и `weekdays` — `unit: 'day'`,
  число дней подряд; сегодняшний день без отметки серию не обнуляет (отсчёт идёт от
  вчерашнего), два пропущенных дня подряд дают `0`; для `weekdays` незапланированные дни не
  разрывают серию и не увеличивают её значение; для `times_per_week` — `unit: 'week'`, число

  «нет серии», а при `atWindowEdge` — «180+ дней подряд».
- **AC5 (А). Сетка и процент за неделю.** `habitWeek(habit, doneDates, todayIso)` покрыта
  тестами: ровно 7 элементов, последний — `todayIso`, будущих дат нет, у каждого дня

  `target` = 7 для `daily`, число запланированных дней окна для `weekdays`, `goalTimes` для
  `times_per_week`; `done` = число отметок в окне; `percent` = округлённое
  `done / target * 100`, не больше 100.
- **AC6 (А). Прогресс чеклиста.** `checklistProgress(items)` покрыта тестами: возвращает

- **AC7 (А). Вкладка «Привычки».** `src/screens/HabitsScreen.tsx` покрыт тестами компонента

- **AC8 (А). Блок привычек на «Сегодня».** `src/components/HabitsToday.tsx` покрыт тестами:

## 3. Модель данных

Миграция `supabase/migrations/0005_habits.sql`.

`habits` — привычка:
- `id uuid pk default gen_random_uuid()`
- `user_id uuid not null default auth.uid() references auth.users (id) on delete cascade`
- `title text not null check (char_length(btrim(title)) between 1 and 80)`
- `note text` — необязательное пояснение («20 минут, любая книга»)
- `goal_type text not null default 'daily' check (goal_type in ('daily','times_per_week','weekdays'))`
- `goal_times smallint not null default 1 check (goal_times between 1 and 7)` — для
  `times_per_week`
- `goal_weekdays smallint[] not null default '{}' check (goal_weekdays <@ array[1,2,3,4,5,6,7]::smallint[])`
  — для `weekdays`, 1 — понедельник
- `position integer not null default 0`
- `archived_at timestamptz`
- `created_at timestamptz not null default now()`, `updated_at timestamptz not null default now()`

`habit_entries` — отметка за день:
- `id uuid pk default gen_random_uuid()`
- `user_id uuid not null default auth.uid() references auth.users (id) on delete cascade`
- `habit_id uuid not null references public.habits (id) on delete cascade`
- `done_on date not null` — **локальная** дата устройства, как `tasks.due_date`
- `created_at timestamptz not null default now()`
- `unique (habit_id, done_on)`

`checklists` — шаблон:
- `id uuid pk`, `user_id uuid not null default auth.uid() …`
- `title text not null check (char_length(btrim(title)) between 1 and 80)`
- `position integer not null default 0`
- `started_at timestamptz` — момент первой отметки текущего прохождения
- `last_completed_at timestamptz` — когда шаблон закрыли в последний раз
- `archived_at timestamptz`
- `created_at`, `updated_at`

`checklist_items` — пункт шаблона и одновременно состояние текущего прохождения:
- `id uuid pk`, `user_id uuid not null default auth.uid() …`
- `checklist_id uuid not null references public.checklists (id) on delete cascade`
- `text text not null check (char_length(btrim(text)) between 1 and 120)`
- `position integer not null default 0`
- `checked_at timestamptz` — отметка в текущем прохождении
- `created_at`

Индексы: `habits (user_id, position)`, `habit_entries (user_id, done_on)`,
`habit_entries (habit_id, done_on)` (уникальный), `checklists (user_id, position)`,
`checklist_items (checklist_id, position)`.

RLS включена на всех четырёх таблицах, по четыре политики с `user_id = auth.uid()`.
`user_id` подставляет значение по умолчанию `auth.uid()` — как в `tasks`. Скриптов на ПК у
этого этапа нет, сервисный ключ не участвует.

Типы фронтенда в `src/lib/types.ts`:

```ts
export type HabitGoalType = 'daily' | 'times_per_week' | 'weekdays'

export interface Habit {
  id: string; title: string; note: string | null
  goalType: HabitGoalType; goalTimes: number; goalWeekdays: number[]
  position: number; archivedAt: string | null
}
/** Отметки приходят плоским списком за окно HABIT_WINDOW_DAYS. */
export interface HabitEntry { habitId: string; doneOn: string }
export interface Checklist {
  id: string; title: string; position: number
  startedAt: string | null; lastCompletedAt: string | null; archivedAt: string | null
}
export interface ChecklistItem {
  id: string; checklistId: string; text: string; position: number; checkedAt: string | null
}
export interface HabitDraft { title: string; note: string | null; goalType: HabitGoalType; goalTimes: number; goalWeekdays: number[] }
```

**Почему отметка — отдельная строка, а не счётчик в привычке.** Серия и процент считаются по
датам, а не по числу: без даты нельзя ни отличить «пропустил вчера» от «пропустил месяц», ни
закрыть забытый вчерашний день. Снятие отметки — удаление строки, отдельного состояния
«отменено» нет.

## 4. Расписание, серии и проценты

Все функции живут в `src/lib/habits.ts`, чистые, работают со строками `YYYY-MM-DD` и
опираются на существующие `addDaysISO`, `diffDaysISO`, `weekdayOf`, `todayISO` из
`src/lib/dates.ts`. Часовой пояс — устройства: отметка привязана к локальной дате, как
`due_date` у задач, и в базу уходит `date`, а не момент времени.

**Расписание.** `daily` — запланирован каждый день. `weekdays` — только дни из
`goalWeekdays`. `times_per_week` — запланирован каждый день: цель гибкая, важно суммарное
число отметок за неделю, а не конкретный день.

**Серия** (`habitStreak`), окно расчёта — `HABIT_WINDOW_DAYS = 180` дней назад от сегодня:
- `daily`: считаем дни подряд назад от сегодня. Если сегодня отмечено — сегодня входит в
  серию; если нет — отсчёт начинается со вчера, и серия не обнуляется до конца суток
  (иначе утром каждый день показывалось бы «нет серии»). Отсутствие отметок и вчера, и
  сегодня даёт `0`.
- `weekdays`: то же, но перебираются только запланированные дни; незапланированный день
  пропускается, не разрывая серию и не увеличивая счётчик. Незакрытый сегодняшний
  запланированный день серию не обнуляет.
- `times_per_week`: серия считается в календарных неделях (пн–вс). Неделя закрыта, если в
  ней ≥ `goalTimes` отметок. Идём назад от текущей недели: текущая входит в серию, только
  когда норма уже выполнена, но незакрытая текущая неделя серию не обнуляет — отсчёт
  начинается с прошлой.
- Если серия упирается в границу окна (180 дней), возвращается `atWindowEdge: true`, и
  подпись становится «180+ дней подряд». Честнее, чем показать ровно 180 и делать вид, что
  это точное число.

**Процент за неделю** (`weekProgress`) — по тому же скользящему окну из 7 дней, что и сетка
(последние 7 дней, включая сегодня): `target` = 7 (`daily`) / число запланированных дней окна
(`weekdays`) / `goalTimes` (`times_per_week`); `done` = число отметок окна; `percent` =
`Math.round(done / target * 100)`, обрезанный сверху до 100. Скользящее окно, а не
календарная неделя: иначе в понедельник утром процент всегда 0 и показатель бесполезен.
Серия для `times_per_week` при этом считается по календарным неделям — процент отвечает на
вопрос «как держусь прямо сейчас», серия — «сколько недель норму закрыл»; расхождение
осознанное и описано в README.

**Сетка** (`habitWeek`) — те же 7 дней: массив `{ iso, weekdayLabel, dayOfMonth, done,
scheduled, isToday }`. Будущих дней в сетке нет, поэтому «серая клетка» всегда означает
пропуск, а не «ещё не наступило».

## 5. Устройство чеклистов

Одно текущее прохождение на шаблон. Состояние отметок хранится в самих пунктах
(`checklist_items.checked_at`), у шаблона есть `started_at` (ставится при первой отметке) и
`last_completed_at`.

Действия:
- **отметить пункт** — `checked_at = now()`; у шаблона с пустым `started_at` заодно
  ставится `started_at`;
- **снять отметку** — `checked_at = null`;
- **Завершить** — `last_completed_at = now()`, `started_at = null`, у всех пунктов
  `checked_at = null` (один `update` по `checklist_id`, вторым запросом — шаблон);
- **Начать заново** — то же без `last_completed_at`: только сброс отметок и `started_at`.

**Почему без таблицы прохождений.** История потребовала бы третьей таблицы
(`checklist_runs` + снимок пунктов на каждый запуск) и экрана истории, которого нет ни в
макете, ни в просьбе владельца: на макете у чеклиста только название и «5 из 12».
Прохождение у одного пользователя всегда одно; «сколько раз я собирал чемодан» — не тот
вопрос, ради которого стоит удваивать схему. Поля `started_at` и `last_completed_at`
закрывают и «когда начал», и «когда закрывал в последний раз». История прохождений — пункт
бэклога; схема к ней готова, добавление `checklist_runs` не потребует переделки шаблонов.

## 6. Интерфейс

Палитра, `FOCUS_RING`, `Section`, `EmptyState` / `ErrorState` / `SkeletonList`,
`WEEKDAY_LABELS`, `LIST_COLORS` / `LIST_COLOR_KEYS` — существующие. Иконка `habits` в
`Icon.tsx` уже есть; для чеклистов берётся существующая `tasks` или `lists`. Новых токенов и

почте.

**Вкладка «Привычки» (`/habits`)**, две секции на одном прокручиваемом экране (как на
макете, без внутренних вкладок):
- Ряд управления: сегмент «Активные / Архив» (`role="tablist"`, как `ViewToggle`) +

  - верх: точка цвета, название `text-[15px]`, справа — серия `text-xs` («5 дней подряд»);
  - подпись: описание цели и процент («каждый день · 71 % за неделю»);
  - сетка 7 клеток `flex gap-1`, каждая — `button h-11 flex-1` с `aria-pressed` и

    подписей дней недели `text-[11px] text-slate-500`;
  - тап по названию открывает редактор привычки.
- `Section` «Чеклисты». Строка (`ChecklistRow`): название, справа «5 из 12», под названием
  полоска прогресса `h-1.5 rounded-full bg-slate-200` с заливкой `bg-blue-600`; если
  прохождение не начато — подпись «Не начат», если закрыт — «Пройден 23 сентября». Тап
  открывает `/checklist/:id`.
- Пустые состояния: «Привычек пока нет» (подсказка «Например: зарядка, вода, чтение
  20 минут») и «Чеклистов пока нет» (подсказка «Например: сборы в поездку») — каждое со

  загруженные данные при повторной загрузке остаются на экране (скелетон показывается только
  при первой загрузке).

**Редактор привычки** (`/habit/new`, `/habit/:id`) — отдельный маршрут, полноэкранный, как
`TaskEditorScreen` (аппаратная «Назад» на Android закрывает редактор): название, заметка,
сегмент цели из трёх вариантов, под ним — только нужное уточнение (stepper «N раз в неделю»,
1–7, `inputMode="numeric"`; или семь кнопок-переключателей дней недели 44×44 с
`aria-pressed`), кнопка «В архив» / «Вернуть из архива», кнопка «Удалить привычку» с
подтверждением в нижнем листе («Удалить привычку? Отметки тоже удалятся»).

**Экран чеклиста** (`/checklist/:id`, `/checklist/new`) — полноэкранный: шапка с названием и
кнопкой «Правка», строка прогресса «5 из 12» с полоской, список пунктов с чекбоксами 44×44
(как `TaskItem`), внизу `sticky` кнопки «Завершить» (`bg-blue-600`, неактивна при нуле
отметок) и «Начать заново» (`border`, с подтверждением, если отмечен хотя бы один пункт). В
режиме «Правка» строки превращаются в поля с кнопками «Удалить», снизу — поле «Новый пункт»
с кнопкой «Добавить» (пункт уходит в конец).

**Блок привычек на «Сегодня»** (`HabitsToday`) — сразу под `QuickAdd`, до «Просрочено»:
заголовок `h2` «Привычки» + счётчик «2 из 4» и ссылка-иконка на вкладку; лента чипсов
`flex gap-2 overflow-x-auto`, по чипу на привычку, запланированную на сегодня: кружок
`h-11 w-11` с галочкой (отмечена — `bg-blue-600`) и название `text-xs` под ним,
`aria-pressed`, `aria-label` «Отметить «Зарядка» на сегодня». Нет подходящих привычек — блока
нет совсем (пустая рамка на главном экране хуже отсутствия блока). Ошибка загрузки привычек —
одна строка `text-xs text-amber-900 bg-amber-100` внутри блока, задачи при этом работают.

**Данные.** `HabitsProvider` + `useHabits` (`ensureLoaded` при монтировании «Сегодня» и
«Привычек»), репозиторий `src/data/habitsRepo.ts`. Отметки оптимистичные: состояние меняется
сразу, зеркало списков держится в `useRef` и используется для откатa при ошибке; ошибка
записи живёт в отдельном поле `actionError` и гаснет после удачного действия — список при
этом не подменяется скелетоном.

## 10. Принятые допущения

1. Три вида цели и никаких других: «каждый день», «N раз в неделю» (1–7), «в выбранные дни
   недели». Цели вида «5 раз в месяц» и количественные («2 литра воды») не поддерживаются —
   привычка отмечается одной галочкой за день, значений не хранит.
2. Отметка привязана к локальной дате устройства (колонка `date`), как `due_date` у задач.
   Часовой пояс нигде не хранится; при переезде в другой часовой пояс прошлые отметки не
   пересчитываются.
3. Отметить можно любой из 7 дней сетки, включая прошедшие: забытый вчерашний день
   закрывается без отдельного экрана. Даты старше 7 дней назад и будущие недоступны — в
   сетке их нет.
4. Серия для целей `daily` и `weekdays` считается в днях, для `times_per_week` — в
   календарных неделях (пн–вс). Иначе «3 раза в неделю» давала бы серию длиной 1–2 дня и
   показатель терял смысл.
5. Незакрытый сегодняшний день (и незакрытая текущая неделя) серию не обнуляют: отсчёт
   начинается с предыдущего периода. Иначе каждое утро показывало бы «нет серии».
6. Окно расчёта — 180 дней; серия, упирающаяся в границу окна, показывается как «180+ дней
   подряд». Полная история отметок в базе остаётся, просто не загружается на экран.
7. Процент считается по скользящему окну из последних 7 дней — тех же, что в сетке, — а не
   по календарной неделе: в понедельник утром календарный процент всегда 0.
8. У чеклиста одно текущее прохождение, история прохождений не хранится (обоснование в
   разделе 5). «Начать заново» и «Завершить» — единственные способы обнулить отметки.
9. Прохождение начинается само, первой отметкой пункта: отдельная кнопка «Начать» была бы
   лишним шагом на пути к первой галочке.
10. Порядок привычек, чеклистов и пунктов задаётся полем `position` при создании (новый
    элемент уходит в конец). Перетаскивание и смена порядка — в бэклоге; как и у списков
    этапа 1, `position` может дублироваться после удалений, на сортировку это не влияет
    (вторичный ключ — название).
11. Архивирование вместо удаления — основной путь: архивная привычка исчезает из «Сегодня» и
    из активного списка, но её отметки сохраняются. Удаление доступно и удаляет отметки
    каскадом.
12. Уникальность отметки задана парой `(habit_id, done_on)` без `user_id`: тогда `upsert`
    работает по естественному ключу, а `user_id` подставляет `default auth.uid()` — не нужно
    передавать его из фронтенда, и второго уникального ограничения, по которому партия могла
    бы упасть, в схеме нет.
13. Проверка «пункт и шаблон принадлежат одному пользователю» на уровне базы не добавляется
    (как и для `tasks.list_id` в этапе 1): пользователь один, а RLS и так отсекает чужие
    строки. Пункт бэклога общий для обеих схем.
14. Блок на «Сегодня» показывает только привычки, запланированные на сегодня; для цели
    «N раз в неделю» это все дни. Чеклистов на «Сегодня» нет — они не привязаны к дате.
15. Привычки грузит `HabitsProvider`, и «Сегодня» тоже вызывает его `ensureLoaded`: строка
    привычек — часть ежедневного экрана. Запросы к задачам и привычкам идут параллельно и
    независимо, ошибка одного не блокирует другой; `DataProvider` о привычках не знает, на
    «Почте» и «Новостях» привычки не грузятся.
16. Напоминаний о привычках нет: механизм этапа 2 умеет только задачи, и связка ждёт пункта
    бэклога «Единая очередь уведомлений».
17. Новых зависимостей и переменных окружения этап не добавляет; скриптов на ПК у него нет —
    все данные создаёт пользователь в приложении.
18. Миграцию `0005` применяет пользователь сам после приёмки; в задаче — только файл в
    репозитории.

## 11. Кандидаты в бэклог

- Push-напоминание о непройденной привычке («в 21:00, если не отмечено») — после «Единой
  очереди уведомлений» из бэклога этапа 2.
- История прохождений чеклиста (`checklist_runs`): когда и за сколько проходил, какие пункты
  чаще всего забываются.
- Генерация чеклиста моделью по описанию («командировка на 3 дня») и готовые шаблоны.
- Статистика привычек за месяц и за год: календарь-месяц, график, доля выполнения, лучший
  результат серии за всё время (сейчас окно 180 дней).
- Перетаскивание для порядка привычек, чеклистов и пунктов; вложенные пункты чеклиста.
- Количественные привычки со значением (стаканы воды, минуты чтения) и цель «N раз в месяц».
- Чеклист из шаблона в задачи: превратить пункты в задачи на день.
- Общая проверка в миграциях, что дочерняя строка (`tasks.list_id`, `checklist_items`,
  `habit_entries`) принадлежит тому же пользователю.
- Объединить `DataProvider`, `MailProvider`, `NewsProvider` и `HabitsProvider` в один каркас
  загрузки (пункт бэклога уже есть; после этого этапа провайдеров четыре — цена пункта
  «обновлять данные при возврате в приложение» выросла вчетверо).
