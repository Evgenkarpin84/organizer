# Дизайн: вкладка «Почта» (этап 3)

Объём чуть больше одной страницы: этап добавляет новый экран-список, новый экран
письма и правку редактора задач. Блоки читаются независимо. Палитра, типографика,
`FOCUS_RING`, `Section`, `EmptyState`/`ErrorState`/`SkeletonList`, правила доступности —
из `stage-0-1-tasks/design.md`. Новых токенов нет, новые только две иконки
(`archive`, `clip`) из раздела 7 спеки.

## Основной сценарий

1. Вкладка «Почта» → список писем, непрочитанные выделены.
2. Тап по строке письма → `/mail/:id`, письмо само отмечается прочитанным.
3. «Создать задачу» → редактор с заполненными названием и заметкой → «Сохранить»
   (возврат на то же письмо).

Убрать письмо: шаг 2 → «В архив». Разобрать пачку: «Назад» → следующая строка.
Основной сценарий — 3 касания.

## 1. Экран «Почта» (`src/screens/MailScreen.tsx`)

Заголовок «Почта» уже есть в `TITLES` (`AppShell`), шапка не меняется. Экран рендерится
внутри `<Route element={<AppShell />}>` вместо `StubScreen stage={3}`.

### Ряды управления (в том же порядке, что на `TasksScreen`)

**Ряд 1 — состояние письма**, сегментированный переключатель, точная копия `ViewToggle`
с экрана «Задачи» (`role="tablist"`, `h-10 flex-1 rounded-lg`, активный —
`bg-white text-slate-900 shadow-sm`):

```tsx
<div role="tablist" aria-label="Фильтр писем" className="mb-2 flex rounded-xl bg-slate-200 p-1">
  {([['all','Все'],['unread','Непрочитанные'],['archived','Архив']] as const).map(([key,label]) => (
    <button key={key} role="tab" type="button" aria-selected={filter === key}
      onClick={() => setFilter(key)}
      className={`flex h-10 flex-1 items-center justify-center gap-1.5 rounded-lg text-sm font-medium ${FOCUS_RING} ${
        filter === key ? 'bg-white text-slate-900 shadow-sm' : 'text-slate-600'}`}>
      {label}
      {key === 'unread' && unreadCount > 0 ? (
        <span className="rounded-full bg-blue-100 px-1.5 text-xs font-normal text-blue-800">{unreadCount}</span>
      ) : null}
    </button>
  ))}
</div>
```

Подпись «Непрочитанные» при крупном шрифте может не поместиться — `text-sm` + бейдж
переносу не подлежат, поэтому у кнопки `min-w-0` и подпись `truncate`; бейдж `shrink-0`.

**Ряд 2 — фильтр по ящику**, лента чипсов ровно по образцу `ListFilterChips`
(`-mx-4 flex gap-2 overflow-x-auto px-4 pb-2 [scrollbar-width:none]`, чип
`inline-flex h-9 shrink-0 items-center gap-2 rounded-full border px-3 text-sm`,
выбранный — `border-transparent bg-slate-900 text-white`). Первый чип «Все ящики»,
далее по чипу на ящик: точка цвета + `label` + число непрочитанных в этом ящике
(`text-xs text-slate-500`, у выбранного — `text-slate-300`). Ряд не рендерится, если
ящик один. Цвет точки — `LIST_COLORS[accountColor(index)].dot`, где
`accountColor(i) = LIST_COLOR_KEYS[i % LIST_COLOR_KEYS.length]` (новых токенов нет).

**Ряд 3 — статус сбора и группировка**, одна строка:

```tsx
<div className="mb-1 flex items-center gap-2">
  <p className="min-w-0 flex-1 text-xs text-slate-500">{statusText}</p>
  <div role="group" aria-label="Группировка" className="flex shrink-0 rounded-lg bg-slate-200 p-0.5">
    {([['date','Дата'],['account','Ящик']] as const).map(([key,label]) => (
      <button key={key} type="button" aria-pressed={group === key} onClick={() => setGroup(key)}
        className={`h-9 rounded-md px-3 text-xs font-medium ${FOCUS_RING} ${
          group === key ? 'bg-white text-slate-900 shadow-sm' : 'text-slate-600'}`}>{label}</button>
    ))}
  </div>
</div>
```

`statusText` в норме: «7 непрочитанных · обновлено сегодня в 12:40». Это и есть главная
цифра экрана — она стоит выше первой строки списка и продублирована бейджем в сегменте.

### Отставание сбора — компонент `MailSyncStatus`

Письма приносит скрипт на ПК, и это видно честно. Источник — `max(lastSyncAt)` и
`lastError` по `mail_accounts`.

| Случай | Что видно |
|---|---|
| Свежо (< 3 ч) | строка `text-xs text-slate-500`: «7 непрочитанных · обновлено сегодня в 12:40» |
| Давно (≥ 3 ч) | вместо строки — `role="status" className="mb-2 rounded-lg bg-amber-100 px-3 py-2 text-xs text-amber-900"`: «Письма не обновлялись 5 часов. Почту собирает скрипт на компьютере — при выключенном ПК новые письма не приходят.» |
| `lastSyncAt` пуст у всех ящиков | тот же amber-блок: «Сбор писем ещё ни разу не запускался на компьютере.» |
| У ящика заполнен `lastError` | amber-блок: «Ящик «Личная bk.ru» не обновляется: неверный пароль приложения. Остальные ящики в порядке.» Текст ошибки — как сохранён скриптом (пароля в нём нет по AC6) |
| Ящиков в базе нет вовсе | amber-блок: «Ящики ещё не настроены. Запустите сбор почты на компьютере: `npm run mail`» |

Порог 3 часа, а не 30 минут расписания: ночью ПК выключен, и красить экран в
предупреждение каждое утро через полчаса — шум.

### Список

Группировка по дате (по умолчанию) — заголовки `Section`: «Сегодня», «Вчера», далее
«15 сентября» (`formatMailGroupTitle`, тот же приём, что `formatDayTitle`, но без
дня недели). Группировка по ящику — заголовки = `label` ящика. `count` у `Section` =
число писем в группе.

Порядок групп: по дате — от свежих к старым; по ящику — в порядке `key` ящиков
(`mail1`…`mail8`), чтобы позиция ящика не прыгала от письма к письму. Внутри группы
всегда `receivedAt desc` — строгая хронология, непрочитанные вверх не всплывают.

Разделение «непрочитанные / остальные» делает не порядок, а вид строки и один тап по
сегменту «Непрочитанные»: непрочитанное — синяя точка слева, отправитель
`font-semibold text-slate-900`, тема `font-medium`; прочитанное — без точки,
отправитель `text-slate-700`, карточка `bg-white/70`.

### Строка письма (`src/components/MailItem.tsx`)

```tsx
<li className="mb-2">
  <button type="button" onClick={() => onOpen(message)}
    className={`flex w-full min-h-[4.5rem] items-start gap-2.5 rounded-xl border border-slate-200 px-3 py-2.5 text-left active:bg-slate-50 ${FOCUS_RING} ${
      unread ? 'bg-white' : 'bg-white/70'}`}>
    {unread ? (
      <>
        <span className="mt-2 h-2 w-2 shrink-0 rounded-full bg-blue-600" aria-hidden="true" />
        <span className="sr-only">Не прочитано.</span>
      </>
    ) : (
      <span className="mt-2 h-2 w-2 shrink-0" aria-hidden="true" />
    )}
    <span className="min-w-0 flex-1">
      <span className="flex items-baseline gap-2">
        <span className={`min-w-0 flex-1 truncate text-[15px] leading-snug ${
          unread ? 'font-semibold text-slate-900' : 'text-slate-700'}`}>{senderLabel(message)}</span>
        <span className="shrink-0 text-xs text-slate-500">{formatMailDate(message.receivedAt, todayIso)}</span>
      </span>
      <span className="mt-0.5 flex items-center gap-1.5">
        <span className={`min-w-0 flex-1 truncate text-sm ${
          message.subject ? (unread ? 'font-medium text-slate-900' : 'text-slate-600') : 'text-slate-500'}`}>
          {subjectOrFallback(message)}
        </span>
        {message.hasAttachments ? (
          <>
            <Icon name="clip" className="h-4 w-4 shrink-0 text-slate-400" />
            <span className="sr-only">Есть вложения.</span>
          </>
        ) : null}
      </span>
      <span className="mt-0.5 line-clamp-1 text-xs text-slate-500 [overflow-wrap:anywhere]">{message.preview}</span>
      <span className="mt-1 flex flex-wrap items-center gap-x-2 gap-y-1 text-xs">
        {hideAccountChip ? null : (
          <span className={`inline-flex items-center rounded-full px-2 py-0.5 ${LIST_COLORS[accountColor(index)].chip}`}>
            {account.label}
          </span>
        )}
        {message.isBulk ? <span className="text-slate-400">Рассылка</span> : null}
        {message.archivedAt ? <span className="text-slate-400">В архиве</span> : null}
      </span>
    </span>
  </button>
</li>
```

- `senderLabel` = `fromName` или, если пусто, `fromEmail`; обе строки `truncate`.
- `subjectOrFallback` = `subject` или «Письмо без темы» (цветом слабее, не курсивом).
- `formatMailDate`: сегодня — «12:40», вчера — «Вчера», в этом году — «15 сент.»,
  иначе — «15 сент. 2025». Время остаётся и при группировке по дате: внутри дня оно
  единственный ориентир.
- `hideAccountChip` = `true`, когда группировка «по ящику» или выбран конкретный ящик
  (правило `hideListChip` из `TaskItem` — не дублировать заголовок).
- «В архиве» показывается только в фильтре «Архив» — в «Все» архивных писем нет.
- Чекбоксов, свайпов и действий прямо из списка нет: строка целиком — одна кнопка
  открытия, промахнуться некуда.

### Состояния экрана

| Состояние | Что видно | Действие пользователя |
|---|---|---|
| Загрузка | Ряды управления отрисованы (фильтры активны), вместо списка `SkeletonList count={4}` с `aria-label="Загрузка писем"` | ждать |
| Норма | `MailSyncStatus` + группы со строками писем | тап по письму |
| Пусто, ящиков нет | `EmptyState icon="mail"` «Писем пока нет», hint «Настройте ящики в `.env` и запустите сбор почты на компьютере: `npm run mail`» | запустить скрипт на ПК |
| Пусто, ящики есть | `EmptyState icon="mail"` «Писем пока нет», hint «Последний сбор: сегодня в 12:40. Новых писем не было.» | ждать |
| Пусто после фильтра | `EmptyState icon="mail"` «Ничего не найдено», hint «Нет писем с такими фильтрами», `action` — кнопка «Сбросить фильтры» (`h-11 rounded-lg border border-slate-300 px-4 text-sm`) | сброс одним тапом |
| Архив пуст | `EmptyState icon="archive"` «В архиве пусто», hint «Сюда попадают письма, убранные кнопкой «В архив»» | вернуться в «Все» |
| Ошибка загрузки, писем нет | только `ErrorState` («Не удалось загрузить письма. Попробуйте ещё раз.») + «Повторить»; пустое состояние не показывается | «Повторить» |
| Ошибка обновления, письма уже есть | `ErrorState` над списком, список из состояния хука остаётся рабочим | «Повторить» |
| Нет сети | `OfflineBanner` из `AppShell` (уже есть); список показывается как есть | — |
| Частичные данные (ящик с `lastError`) | Список полный, сверху amber-строка про конкретный ящик | починить пароль на ПК |

Два разных пустых текста («Писем пока нет» и «Ничего не найдено») — требование AC7:
пустой ящик и пустой фильтр требуют разных действий.

### Хранение выбора

`localStorage`: `mail.filter`, `mail.group`, `mail.account`. Ящик тоже сохраняется —
экран письма живёт отдельным маршрутом и размонтирует список, без сохранения возврат
«Назад» сбрасывал бы фильтр. Если сохранённого ящика больше нет в `mail_accounts` —
молча `all`.

## 2. Экран письма (`src/screens/MailMessageScreen.tsx`, `/mail/:id`)

Маршрут **вне** `AppShell`, как `/task/:id`: полноэкранный, аппаратная «Назад» на
Android возвращает в список, а не выходит из приложения.

### Шапка

Та же разметка, что у `TaskEditorScreen`: `sticky top-0 z-20 h-[calc(3.5rem+env(safe-area-inset-top))]`,
слева текстовая кнопка «Назад» (`h-11 px-3 text-sm text-slate-600`, `onClick={() => navigate(-1)}`),
по центру `<h1 className="text-base font-semibold">Письмо</h1>`, справа распорка
`h-11 w-16` для симметрии. Отдельной иконки «стрелка назад» не заводим — в проекте уже
принята текстовая кнопка возврата.

### Содержимое

```tsx
<div className="flex-1 space-y-3 px-4 py-4">
  <h2 className={`text-lg leading-snug font-semibold [overflow-wrap:anywhere] ${
    message.subject ? 'text-slate-900' : 'text-slate-500'}`}>{subjectOrFallback(message)}</h2>

  <div className="rounded-xl border border-slate-200 bg-white p-3">
    <p className="text-sm font-medium text-slate-900 [overflow-wrap:anywhere]">{senderLabel(message)}</p>
    <p className="mt-0.5 text-xs break-all text-slate-500">{message.fromEmail}</p>
    <p className="mt-1 text-xs text-slate-500 [overflow-wrap:anywhere]">Кому: {toLine}</p>
    <p className="mt-1 flex flex-wrap items-center gap-2 text-xs text-slate-500">
      <span>{formatMailFullDate(message.receivedAt)}</span>
      <span className={`inline-flex items-center rounded-full px-2 py-0.5 ${LIST_COLORS[color].chip}`}>{account.label}</span>
      {message.isBulk ? <span className="text-slate-400">Рассылка</span> : null}
    </p>
    {message.hasAttachments ? (
      <ul className="mt-2 space-y-1">
        {message.attachmentNames.map((name) => (
          <li key={name} className="flex items-start gap-1.5 text-xs text-slate-600">
            <Icon name="clip" className="mt-0.5 h-3.5 w-3.5 shrink-0 text-slate-400" />
            <span className="min-w-0 [overflow-wrap:anywhere]">{name}</span>
          </li>
        ))}
        <li className="text-xs text-slate-400">Файлы не скачиваются — откройте письмо в почтовом клиенте.</li>
      </ul>
    ) : null}
  </div>

  <div className="rounded-xl border border-slate-200 bg-white p-4">
    <p className="text-[15px] leading-relaxed whitespace-pre-wrap [overflow-wrap:anywhere]">{message.bodyText}</p>
  </div>
</div>
```

- `toLine`: до трёх адресов через запятую, дальше «и ещё 2». Пустой `toEmails` — строка
  «Кому» не рендерится.
- `formatMailFullDate`: «15 сентября, 12:40» (при другом годе — с годом).
- **Тело письма.** `whitespace-pre-wrap` сохраняет абзацы из `text/plain`;
  `[overflow-wrap:anywhere]` ломает длинные ссылки и склеенные слова из рассылок —
  горизонтальной прокрутки на 360 px нет ни при каком письме. Ссылки не кликабельны:
  автолинковка чужого текста — лишний риск, адрес виден и копируется выделением.
- **Обрезка** (`bodyTruncated`) — сразу под телом:
  `<p role="status" className="rounded-lg bg-amber-100 px-3 py-2 text-xs text-amber-900">`
  «Текст письма сохранён не полностью. Полное письмо — в почтовом клиенте.» Для рассылки
  добавляется « У рассылок сохраняются первые 500 символов.»
- **Пустое тело** (письмо было только HTML сверх лимита, текстовой части нет): вместо
  карточки тела — `<p className="rounded-xl border border-dashed border-slate-300 p-4 text-sm text-slate-500">`
  «Текст письма не сохранён: он слишком большой или письмо состоит только из вложений.
  Откройте письмо в почтовом клиенте.» Пустой белой карточки, похожей на сбой, не будет.
- **Письмо, состоящее из одного HTML**, отдельного состояния не имеет: скрипт уже
  превратил его в текст, экран не знает про HTML. Ломаную вёрстку выдают только пустые
  строки — их сжимает `htmlToPlainText` (AC4).

## 3. Задача из письма

`draftFromMail(message, account)` — чистая функция в `src/lib/mail.ts`, возвращает
`TaskDraft` поверх `emptyDraft()`:

| Поле | Значение |
|---|---|
| `title` | тема письма; без темы — `Письмо от <senderLabel>`; обрезка до 200 символов (предел поля названия в редакторе) |
| `note` | `От: Иван Петров <ivan@bk.ru>` + пустая строка + первые 500 символов `bodyText` (хвостовые пробелы срезаны). Пустое тело — только первая строка |
| остальные поля | как в `emptyDraft()`: без срока, приоритет 0, без повтора и напоминания |

Срок не подставляется намеренно: дата письма — не дедлайн задачи, а угадывать «завтра»
за пользователя хуже, чем оставить поле пустым, — он и так уже в редакторе.

Переход: `navigate('/task/new', { state: { draft: draftFromMail(...) } })`.
`TaskEditorScreen` меняется в одном месте — начальное значение состояния:

```tsx
const location = useLocation()
const incoming = (location.state as { draft?: TaskDraft } | null)?.draft ?? null
const [draft, setDraft] = useState<TaskDraft | null>(() => (id ? null : (incoming ?? emptyDraft())))
```

Что видит пользователь: обычный редактор «Новая задача» с заполненными «Название» и
«Заметка». Автофокус в название остаётся — курсор в конце, тему можно сократить, не
стирая всё. Остальные поля пустые и подсвечивают, что осталось решить: срок и список.

Куда возвращается: «Сохранить» и «Отмена» одинаково делают `navigate(-1)` — обратно на
то же письмо, а не в список. Пользователь видит контекст и может тут же нажать
«В архив». Отдельного тоста «Задача создана» нет: возврат на письмо и есть подтверждение,
а связи «письмо ↔ задача» на этом этапе в базе не существует (допущение 15 спеки),
поэтому отметки «задача создана» на письме тоже не будет.

## 4. Новые иконки (`src/components/Icon.tsx`)

`IconName` пополняется на `'archive' | 'clip'`; стиль путей — тот же
(`viewBox 0 0 24 24`, `strokeWidth 1.8`, без заливки):

```
archive: ['M3 6h18v4H3z', 'M5 10v9a1 1 0 0 0 1 1h12a1 1 0 0 0 1-1v-9', 'M10 14h4']
clip:    ['M20 11.5 12.5 19a4.5 4.5 0 0 1-6.4-6.4l8-8a3 3 0 1 1 4.2 4.2l-8 8a1.5 1.5 0 1 1-2.1-2.1l7.2-7.2']
```

Обе — декоративные (`aria-hidden` внутри `Icon`), смысл несут соседние `sr-only`
(«Есть вложения») и подписи кнопок.

## 5. Доступность и удобство на телефоне

- Строка письма — одна кнопка `min-h-[4.5rem]` на всю ширину: цель нажатия сильно
  больше 48dp, соседние строки разделены `mb-2`. Никаких мелких целей внутри строки.
- Кнопки нижней панели письма — `h-12`, в нижней трети экрана: всё достаётся большим
  пальцем одной рукой. «Назад» вверху дублируется аппаратной кнопкой Android.
- Чипсы ящиков `h-9` + `px-3` в ленте с `gap-2` — как уже принято в `ListFilterChips`;
  сегменты фильтра `h-10` внутри ряда высотой 48 с паддингом контейнера.
- Крупный системный шрифт: у строки письма `min-h-*`, а не `h-*`; мета-строка
  `flex-wrap`; в сегментах подписи `truncate`; нижняя панель — два ряда, а не три
  кнопки в строку, поэтому подписи не режутся.
- Одна строка = одна строка текста: `truncate` у отправителя и темы, `line-clamp-1` у
  превью. Текст письма, наоборот, никогда не обрезается визуально —
  `whitespace-pre-wrap` + `[overflow-wrap:anywhere]`, без горизонтальной прокрутки.
- Контраст: `text-slate-500`/`text-slate-600` на белом, `bg-amber-100 text-amber-900`
  для отставания сбора, `text-rose-700 на bg-rose-50` для ошибок — палитра этапа 0–1.
  `text-slate-400` — только у продублированных подписей («Рассылка», имя файла).
- Непрочитанность не держится на одном цвете: точка + насыщенность шрифта + `sr-only`
  «Не прочитано» в начале строки.
- Порядок фокуса = порядок DOM: сегменты фильтра → чипсы ящиков → группировка → строки
  писем → нижняя навигация. На экране письма: «Назад» → тема → отправитель → тело →
  «Создать задачу» → «Прочитано» → «В архив» (панель стоит в DOM после контента и
  визуально снизу — порядок совпадает).
- Заголовки: `h1` «Почта» в `AppShell` / «Письмо» в шапке экрана письма, `h2` —
  заголовки групп (`Section`) и тема письма. Пропусков уровней нет.
- `FOCUS_RING` на всех интерактивных элементах; текстов ошибок без кодов, технические
  детали — только `console.error` (правило этапа 0–1).

## Что осознанно НЕ делаем

- Поиск по письмам и фильтр по отправителю — вне AC, кандидат бэклога (разд. 13 спеки).
- «Показать ещё» / бесконечная прокрутка — список ограничен 200 письмами (допущение 13).
- Кнопка «Показать письмо полностью» — текста максимум 2000 символов, прокрутка дешевле
  лишнего элемента.
- Кликабельные ссылки и автолинковка в теле письма — чужой текст, лишний риск.
- Свайпы «архивировать/прочитать» по строке списка — правило этапа 0–1: случайные жесты.
- Массовые действия и выбор нескольких писем — писем в день десятки, чекбоксы съедят
  строку.
- Отметка «задача создана» и переход к созданной задаче из письма — связи в базе нет.
- Показ HTML-версии, картинок и вложений — не хранятся принципиально (разд. 4 спеки).
- Восстановление позиции прокрутки списка при возврате из письма — требует стора
  прокрутки, вне AC.
- Кнопка «Собрать почту сейчас» на экране — фронтенд не может запустить скрипт на ПК;
  вместо неё честная строка статуса.
- Push о новом письме и отдельная лента рассылок — кандидаты бэклога.
- Отдельный экран «Ящики» с состоянием синхронизации — состояние показывает строка
  статуса, полноценный экран избыточен на четыре ящика.

## Решения дизайнера (спорные места)

1. **Непрочитанные не всплывают наверх группы.** Порядок строго хронологический, иначе
   при открытии письмо прыгает по списку. Разделение даёт сегмент «Непрочитанные» —
   один тап, и он же несёт главную цифру.
2. **Дублирующей секции «Непрочитанные» над группами нет** — одно письмо не должно
   встречаться в списке дважды.
3. **Три ряда управления (состояние, ящик, группировка+статус)** вместо двух: фильтр по
   ящику требуется заданием, а мешать его с «Все/Непрочитанные/Архив» в один ряд
   нельзя — это разные измерения. Ряд ящиков скрывается, если ящик один.
4. **Группировка — компактный парный переключатель в строке статуса**, а не полноширинный
   сегмент: это настройка вида, она не должна весить столько же, сколько фильтр.
5. **Порог «давно не обновлялось» — 3 часа**, не 30 минут расписания: ночью ПК выключен,
   и утреннее предупреждение через полчаса простоя было бы шумом.
6. **Ошибка ящика — amber, а не rose.** Экран работает, письма показаны; красный цвет
   зарезервирован за ошибкой загрузки самого приложения.
7. **`/mail/:id` — отдельный маршрут вне `AppShell`**, как редактор задачи: аппаратная
   «Назад» должна закрывать письмо, а нижняя навигация под текстом письма бесполезна.
8. **Возврат «Назад» — текстовая кнопка**, а не новая иконка-стрелка: в проекте уже
   принят текстовый возврат («Отмена» в редакторе), а лимит новых иконок — две по спеке.
9. **Действия письма — внизу, а не в шапке.** Шапка недосягаема большим пальцем, а
   действия здесь основные, а не служебные.
10. **Архивирование без подтверждения**, в отличие от удаления задачи: письмо остаётся в
    базе и в ящике, отмена — один тап «Из архива».
11. **Срок задачи из письма не подставляется** — дата письма не равна дедлайну.
12. **Заметка начинается со строки «От: …»**, а не с текста письма: адрес — единственное,
    чего не будет в названии, и он нужен, чтобы вспомнить контекст через неделю.
13. **После сохранения задачи пользователь возвращается на письмо**, а не в список:
    следующее логичное действие — «В архив», и оно рядом.
14. **Цвета ящиков берутся из `LIST_COLOR_KEYS` по индексу**, без новой палитры и без
    поля цвета в `mail_accounts`: четыре ящика надёжно различаются, схема не меняется.
15. **Фильтр по ящику сохраняется в `localStorage`** наравне с фильтром и группировкой —
    экран письма размонтирует список, иначе возврат сбрасывал бы выбор.
16. **Письмо с пустым телом показывается объяснением, а не пустой карточкой** — иначе
    ограничение в 256 КБ выглядит как поломка приложения.
