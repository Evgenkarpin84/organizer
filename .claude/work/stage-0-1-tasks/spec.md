# Спецификация: этапы 0–1 — каркас PWA и задачи

Статус: критерии приёмки заморожены 16.09.2026. Всё новое сверх них — в `BACKLOG.md`.

## 1. Цель и рамки

Цель: работающее PWA-приложение, которое ставится на Android с рабочего стола, пускает внутрь только владельца и умеет вести задачи с планировщиком на неделю.

Входит:
- каркас: вход, нижняя навигация из пяти вкладок, установка на телефон, экран «Supabase не настроен»;
- задачи: создание, редактирование, удаление, отметка выполнения, срок (дата и необязательное время), приоритет, списки, повторения, быстрый ввод;
- экраны «Сегодня» и «Предстоящие» (неделя по дням);
- SQL-миграция со схемой и RLS в репозитории.

Не входит:
- push-напоминания (этап 2) — в модели данных есть только поле `remind_at`;
- почта, новости, привычки — вкладки-заглушки;
- деплой на хостинг;
- применение миграции к реальной базе (делает пользователь отдельно);
- офлайн-редактирование: кэшируется только оболочка приложения.

## 2. Критерии приёмки

Проверка: `А` — автоматически (сборка, типы, тесты, линтер), `Р` — вручную в браузере, `Б` — только после подключения реальной базы.

- AC1 (А). `npm run build`, `npm run typecheck`, `npm run lint`, `npm test` проходят без ошибок.
- AC2 (А). Без переменных `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` приложение не падает, а показывает экран «Supabase не настроен» с инструкцией.
- AC3 (Р). Сборка отдаёт манифест и service worker; в манифесте есть иконки 192, 512 и maskable 512, `display: standalone`, относительные `start_url` и `scope`.
- AC4 (Б). Вход: адрес почты, кнопка «Получить код», ввод шестизначного кода, вход в приложение. Регистрация невозможна: клиент передаёт `shouldCreateUser: false`.
- AC5 (Б). Сессия сохраняется между запусками приложения; есть выход из аккаунта.
- AC6 (А). Нижняя навигация состоит из пяти вкладок: Сегодня, Задачи, Почта, Новости, Привычки. Последние три показывают заглушку с номером этапа.
- AC7 (Б). Задачу можно создать, отредактировать (название, заметка, список, дата, время, приоритет, повтор), удалить и отметить выполненной.
- AC8 (А). Быстрый ввод распознаёт дату, время, приоритет, список и повтор из строки на русском и убирает распознанные части из названия. Разобранные значения показываются до сохранения.
- AC9 (А). Обычная задача при отметке выполнения получает `completed_at`; повторяющаяся не закрывается, а переносится на следующую дату по правилу повтора, и в `last_completed_at` пишется момент отметки.
- AC10 (А). Следующая дата повтора всегда строго больше сегодняшней: просроченная ежедневная задача при отметке переносится на завтра, а не на прошедший день.
- AC11 (А). Ежемесячный повтор с числом 31 в коротком месяце переносится на последний день этого месяца.
- AC12 (А). Экран «Сегодня» содержит три раздела: «Просрочено», «Сегодня» и «Выполнено сегодня». Просроченным считается срок строго раньше сегодняшнего дня.
- AC13 (А). Экран «Предстоящие» показывает семь дней начиная с сегодняшнего, каждый день подписан датой и днём недели по-русски, пустые дни видны и подписаны.
- AC14 (А). В «Предстоящих» повторяющаяся задача показывается на всех подходящих днях, а отметить выполнение можно только на её ближайшей реальной дате.
- AC15 (Б). Списки: создание, переименование, удаление. При удалении списка задачи не удаляются, а остаются без списка.
- AC16 (А). Миграция `supabase/migrations/0001_init.sql` создаёт таблицы `lists` и `tasks`, включает RLS, заводит политики на чтение и запись только своих строк и индексы под выборки по дате и по списку.
- AC17 (А). Во фронтенде нет ключа `service_role`; `.env` в `.gitignore`; в репозитории есть `.env.example` с пустыми значениями.
- AC18 (А). Интерфейс на русском, mobile-first: нижняя панель не перекрывает контент, основные действия достижимы одной рукой.
- AC19 (Б). Ошибки сети и Supabase показываются понятным текстом, приложение остаётся работоспособным.
- AC20 (А). README описывает настройку Supabase (пользователь-владелец, отключение регистрации, шаблон письма с кодом, применение миграции), запуск и переменные окружения.

## 3. Модель данных

`lists`: `id uuid pk`, `user_id uuid` (по умолчанию `auth.uid()`), `name text` (1–40 символов), `color text` (ключ из фиксированного набора), `position int`, `created_at timestamptz`.

`tasks`: `id uuid pk`, `user_id uuid` (по умолчанию `auth.uid()`), `list_id uuid null` (`on delete set null`), `title text` (1–200), `note text null`, `due_date date null`, `due_time time null`, `remind_at timestamptz null` (для этапа 2, в этой задаче не заполняется), `priority smallint 0..3`, `repeat_type text` (`none`, `daily`, `weekly`, `monthly`), `repeat_interval smallint` (только для `daily`), `repeat_weekdays smallint[]` (1–7, пн–вс, для `weekly`), `repeat_day_of_month smallint null` (для `monthly`), `completed_at timestamptz null`, `last_completed_at timestamptz null`, `created_at`, `updated_at`.

Индексы: `tasks(user_id, due_date)`, `tasks(user_id, completed_at)`, `tasks(user_id, list_id)`, `lists(user_id, position)`.

RLS: включена на обеих таблицах, по политике на `select`, `insert`, `update`, `delete` с условием `user_id = auth.uid()`. Триггер обновляет `updated_at`.

Часовой пояс: срок хранится как дата и время без зоны и трактуется в локальном поясе устройства.

## 4. Повторения

- `daily` — каждые `repeat_interval` дней (по умолчанию 1).
- `weekly` — в выбранные дни недели, каждую неделю.
- `monthly` — в указанное число месяца, с переносом на последний день короткого месяца.

При отметке выполнения повторяющейся задачи: `last_completed_at = now()`, `due_date` = ближайшая дата по правилу, строго позже сегодняшнего дня; `completed_at` остаётся пустым. Снять такую отметку нельзя — осознанное упрощение.

В «Предстоящих» повторяющиеся задачи разворачиваются на все подходящие дни вперёд. Отметить можно только ближайшую реальную дату, остальные вхождения открывают карточку задачи.

## 5. Быстрый ввод

Строка разбирается детерминированно, без обращения к модели:
- дата: `сегодня`, `завтра`, `послезавтра`, `в понедельник`…`в воскресенье`, `пн`…`вс`, `через N дней`, `через неделю`, `15.09`, `15.09.2026`;
- время: `в 18`, `в 18:30`, `18:30`;
- приоритет: `!1` низкий, `!2` средний, `!3` высокий;
- список: `#Работа` — совпадение по имени без учёта регистра; если списка нет, текст остаётся в названии;
- повтор: `каждый день`, `каждые N дней`, `каждый вторник`, `каждую неделю`, `каждый месяц`.

Распознанные фрагменты удаляются из названия; остальное становится названием задачи. Пустое название после разбора — ошибка ввода.

## 6. Вход

Supabase Auth, одноразовый код из письма (`signInWithOtp` с `shouldCreateUser: false`, затем `verifyOtp` с `type: 'email'`). Magic link не используется: на Android ссылка открывается в браузере, а не в установленном приложении. Сессия хранится библиотекой в localStorage. Настройка на стороне Supabase описывается в README.

**Изменение после приёмки (23.09.2026).** Вход переведён на почту и пароль (`signInWithPassword`). Причина: Supabase на бесплатном тарифе не даёт редактировать шаблоны писем без своего SMTP, поэтому в письме приходила ссылка вместо кода, плюс у встроенной почты лимит в пару писем в час. AC4 считается выполненным в форме «вход только для владельца, регистрация закрыта»; возврат к коду из письма — после подключения SMTP, пункт в `BACKLOG.md`.

## 7. PWA

`vite-plugin-pwa`, `registerType: autoUpdate`, кэш оболочки приложения. Манифест: имя «Органайзер», `display: standalone`, `orientation: portrait`, относительные `start_url` и `scope`, цвета темы, иконки 192, 512 и maskable 512. Иконки генерируются скриптом `scripts/generate-icons.mjs` без внешних зависимостей.

## 8. Стек

Vite, React, TypeScript, Tailwind CSS (плагин `@tailwindcss/vite`), `vite-plugin-pwa`, `@supabase/supabase-js`, `react-router-dom` (HashRouter — чтобы приложение работало на статическом хостинге в подкаталоге), `date-fns` с русской локалью, Vitest + Testing Library + jsdom, ESLint (flat config) с typescript-eslint.

## 11. Принятые допущения

1. Вход по одноразовому коду, magic link не поддерживается.
2. `repeat_interval` применяется только к ежедневному повтору; недельный и месячный идут с интервалом 1.
3. Повторяющуюся задачу нельзя «раз-отметить»: отметка сразу переносит срок.
4. Задача без даты попадает только в раздел «Все» на вкладке «Задачи».
5. Быстрый ввод не создаёт новые списки: неизвестный `#тег` остаётся частью названия.
6. Цвет списка выбирается из фиксированного набора.
7. Экран «Предстоящие» показывает ровно 7 дней, включая сегодняшний.
8. Офлайн доступна только оболочка приложения; данные требуют сети.
9. Часовой пояс берётся из устройства и нигде не хранится.
10. Приоритет по умолчанию — «без приоритета» (0).
