# Дизайн: каркас PWA и задачи (этапы 0–1)

Объём больше одной страницы — задача покрывает два этапа сразу (каркас + модуль задач).
Разбита по экранам, каждый блок читается независимо.

## Основной сценарий

1. Открыть приложение с рабочего стола → вкладка «Сегодня» (стартовая).
2. Ввести строку в поле быстрого ввода вверху («купить корм завтра в 18 !2»).
3. Проверить чипсы разбора под полем → Enter / кнопка «Добавить».
4. Отметить выполненное касанием чекбокса.

Редактирование задачи — 2 касания: тап по карточке → редактор → «Сохранить».

## Каркас

`AppShell` (`src/components/AppShell.tsx`) — обёртка авторизованной части, три слоя.

```
<div class="flex min-h-full flex-col bg-slate-50 text-slate-900">
  <header class="sticky top-0 z-20 flex h-14 items-center gap-2 border-b border-slate-200
                 bg-white/95 px-4 backdrop-blur
                 pt-[env(safe-area-inset-top)] h-[calc(3.5rem+env(safe-area-inset-top))]">
    <h1 class="flex-1 truncate text-lg font-semibold">Сегодня</h1>
    {/* слот справа: кнопка-иконка 44×44, напр. «Выйти» */}
  </header>

  <main class="flex-1 px-4 pt-3 pb-[calc(4.5rem+env(safe-area-inset-bottom))]">…</main>

  <BottomNav />
</div>
```

- Отступ снизу у `main` = высота панели (64px) + safe-area + 8px. Контент не уезжает
  под панель — это AC18.
- `index.html` уже содержит `viewport-fit=cover`, поэтому `env(safe-area-inset-*)` работает.
- Прокручивается только `main`; шапка липкая, панель фиксированная.

### `BottomNav`

```
<nav class="fixed inset-x-0 bottom-0 z-30 border-t border-slate-200 bg-white
            pb-[env(safe-area-inset-bottom)]">
  <ul class="mx-auto flex max-w-md">
    <li class="flex-1">
      <NavLink class="flex h-16 flex-col items-center justify-center gap-1
                      text-[11px] leading-none
                      text-slate-500 aria-[current=page]:text-blue-600
                      aria-[current=page]:font-medium
                      focus-visible:outline-2 focus-visible:outline-blue-600 focus-visible:-outline-offset-2">
        <Icon class="h-6 w-6" aria-hidden="true" />
        <span>Сегодня</span>
      </NavLink>
```

Пять вкладок в порядке: **Сегодня / Задачи / Почта / Новости / Привычки**.
Зона нажатия 64px по высоте × 1/5 ширины (≥ 72px на 360dp) — с запасом к 48dp.
Активная вкладка — цвет + жирность + `aria-current="page"` (не только цвет, AC доступности).

## Экран «Сегодня» (`TodayScreen`)

Шапка: «Сегодня» + мелкой строкой дата `formatDayTitle` без слова «Сегодня» — `text-xs text-slate-500`.

Порядок сверху вниз: `QuickAdd` → «Просрочено» → «Сегодня» → «Выполнено сегодня».

| Состояние | Что видно | Действие |
|---|---|---|
| Загрузка | `QuickAdd` активен + 3 скелетона `h-14 animate-pulse rounded-xl bg-slate-200` | ждать |
| Пусто (нет задач вообще) | Иконка, «Задач пока нет», «Добавьте первую в поле вверху» + стрелка вверх | ввод в `QuickAdd` |
| Пусто на сегодня, задачи есть | «На сегодня всё чисто», ссылка-кнопка «Посмотреть предстоящие» → вкладка «Задачи» | переход |
| Норма | Разделы с задачами; пустые разделы скрыты (кроме случая выше) | отметка/тап |
| Ошибка сети | `ErrorState` вместо списка, `QuickAdd` заблокирован с подписью | «Повторить» |
| Частично | Список из кэша React-состояния + жёлтая полоса «Не удалось обновить данные» | «Повторить» |

Заголовок раздела:
`<h2 class="mt-5 mb-2 flex items-center gap-2 text-sm font-semibold text-slate-600">`
+ счётчик `<span class="rounded-full bg-slate-200 px-2 py-0.5 text-xs">3</span>`.
«Просрочено» — `text-rose-600`, счётчик `bg-rose-100 text-rose-700`.

«Выполнено сегодня» — сворачиваемый `<details>`, по умолчанию закрыт, если > 3 задач;
задачи внутри `text-slate-400 line-through`.

### `QuickAdd`

```
<form class="sticky top-[calc(3.5rem+env(safe-area-inset-top))] z-10 -mx-4 bg-slate-50 px-4 pb-2 pt-1">
  <div class="flex items-center gap-2 rounded-xl border border-slate-300 bg-white px-3
              focus-within:border-blue-500 focus-within:ring-2 focus-within:ring-blue-100">
    <input class="h-12 flex-1 bg-transparent text-base outline-none placeholder:text-slate-400"
           placeholder="Новая задача…" enterKeyHint="done" />
    <button class="h-11 w-11 shrink-0 rounded-lg text-blue-600 disabled:text-slate-300"
            aria-label="Добавить задачу">＋</button>
  </div>
  <div class="mt-1.5 flex flex-wrap gap-1.5">{чипсы разбора}</div>
</form>
```

- Чипсы разбора появляются по мере ввода (AC8): `rounded-full bg-blue-50 px-2 py-1 text-xs
  text-blue-700`. Содержат «Завтра», «18:30», «Средний», «#Работа», «Каждый день».
  Рядом чип с очищенным названием `bg-slate-100 text-slate-700`.
- Область чипсов в `aria-live="polite"`, чтобы разбор озвучивался.
- Ошибка «пустое название после разбора»: поле `border-rose-400`, подпись
  `text-xs text-rose-600` «Не осталось названия — допишите, что нужно сделать».
  **Текст в поле не стирается** — исправление без начала заново.
- Кнопка «＋» неактивна при пустой строке. Отправка по Enter.
- Подсказка синтаксиса — иконка «?» в шапке экрана, открывает `<details>`-панель со списком
  примеров из раздела 5 спеки. Скрыта по умолчанию, чтобы не занимать первый экран.

## Экран «Задачи» (`TasksScreen`)

Шапка: заголовок «Задачи» + кнопка-иконка «Списки» (44×44, `aria-label="Управление списками"`).

Под шапкой — два ряда управления (оба липкие вместе с шапкой):

1. Сегментированный переключатель `ViewToggle`:
```
<div role="tablist" class="flex rounded-xl bg-slate-200 p-1">
  <button role="tab" class="h-10 flex-1 rounded-lg text-sm font-medium
      aria-selected:bg-white aria-selected:text-slate-900 aria-selected:shadow-sm text-slate-600">
```
Вкладки «Предстоящие» (по умолчанию) и «Все».

2. `ListChips` — горизонтальная лента `flex gap-2 overflow-x-auto -mx-4 px-4 pb-2
   [scrollbar-width:none]`. Первый чип «Все», затем списки, затем «Без списка».
   Чип: `h-9 shrink-0 rounded-full border px-3 text-sm`, выбранный —
   `border-transparent bg-slate-900 text-white`, невыбранный — `border-slate-300 bg-white`
   + точка цвета `h-2 w-2 rounded-full` из `LIST_COLORS[color].dot`.
   Фильтр — одиночный выбор, применяется к обеим вкладкам.

### Вкладка «Предстоящие»

Семь дней от сегодняшнего (`buildWeek`). Каждый день — секция с липким заголовком:
```
<h2 class="sticky top-[…] z-10 bg-slate-50 py-2 text-sm font-semibold text-slate-600">
  Сегодня, 16 сентября
</h2>
```
Подпись берётся из `formatDayTitle` (уже даёт «Сегодня» / «Завтра» / «Пт, 18 сентября»).
Пустой день **виден** (AC13): вместо списка строка
`<p class="py-2 pl-1 text-sm text-slate-400">Свободно</p>`.
Сегодняшняя секция дополнительно помечена `text-blue-700`.

### Вкладка «Все»

Плоский список `activeTasks`, сортировка по умолчанию: сначала задачи со сроком по
возрастанию даты и времени, потом приоритет по убыванию, потом название. Задачи без даты
(допущение 4 спеки) идут отдельной группой «Без даты» в конце. Выполненные не показываются.

### Управление списками (`ListsSheet`)

Нижний лист (`role="dialog" aria-modal="true"`), высота по контенту, максимум `max-h-[80vh]`:
`fixed inset-x-0 bottom-0 rounded-t-2xl bg-white p-4 pb-[calc(1rem+env(safe-area-inset-bottom))]`,
подложка `fixed inset-0 bg-slate-900/40`.

- Строка списка: точка цвета, имя, кнопка «Переименовать» (иконка карандаша, 44×44),
  кнопка «Удалить» (иконка корзины, 44×44, `text-rose-600`).
- Переименование — инлайн: имя заменяется на `input` в той же строке, кнопки
  «Сохранить»/«Отмена». Без отдельного экрана.
- Удаление — подтверждение в том же листе: строка раскрывается в
  `bg-rose-50 rounded-lg p-3` с текстом «Удалить «Работа»? Задачи останутся без списка»
  и кнопками «Отмена» / «Удалить». Это и есть защита разрушающего действия (AC15).
- Создание — поле снизу листа: `input` + кнопка «Создать», под ним ряд из шести кружков
  цвета `LIST_COLOR_KEYS` (`h-10 w-10 rounded-full`, выбранный с `ring-2 ring-offset-2
  ring-slate-900`, `aria-pressed`). Лимит 40 символов — счётчик появляется с 30-го.

## Карточка задачи (`TaskItem`)

```
<li class="flex items-start gap-3 rounded-xl border border-slate-200 bg-white px-3 py-2.5
           mb-2 active:bg-slate-50">
  {левый слот 44×44}
  <button class="min-w-0 flex-1 py-1 text-left">           {/* открывает редактор */}
    <div class="flex items-start gap-2">
      <span class="min-w-0 flex-1 text-[15px] leading-snug">Купить корм</span>
      <span class="mt-1.5 h-2 w-2 shrink-0 rounded-full bg-rose-500" aria-hidden="true" />
    </div>
    <div class="mt-1 flex flex-wrap items-center gap-x-2 gap-y-1 text-xs text-slate-500">
      <span class="text-rose-600 font-medium">Вчера, 18:30</span>
      <span class="inline-flex items-center gap-1 rounded-full bg-blue-100 px-2 py-0.5 text-blue-800">Работа</span>
      <span>↻ Каждый день</span>
    </div>
  </button>
</li>
```

- **Чекбокс** (левый слот, обычная задача):
  `<button class="flex h-11 w-11 shrink-0 items-center justify-center" role="checkbox"
  aria-checked="false" aria-label="Отметить «Купить корм» выполненной">` внутри визуальный
  кружок `h-6 w-6 rounded-full border-2 border-slate-300`. Отмеченный — `bg-blue-600
  border-blue-600` с галочкой. Зона 44×44 внутри строки высотой ≥ 56 — фактическая цель ≥ 48dp.
- **Приоритет** — точка справа от названия, `PRIORITY_DOT[priority]`; при 0 не рендерится.
  Дублируется текстом только для скринридера: `<span class="sr-only">Приоритет: высокий</span>`.
  Высокий приоритет дополнительно делает название `font-medium`.
- **Подпись срока** — `formatDueLabel`. Просрочено → `text-rose-600 font-medium`,
  сегодня → `text-blue-700`, иначе `text-slate-500`.
- **Список** — чип `LIST_COLORS[color].chip`. Не показывается, когда активен фильтр по
  этому же списку (дублирование).
- **Повтор** — `↻ Каждый день` / `↻ Пн, Ср` / `↻ 31 числа`, `text-slate-500`.
- **Виртуальное вхождение повтора** (`virtual: true`, AC14): левый слот — **не кнопка**,
  а неинтерактивная иконка повтора
  `<span class="flex h-11 w-11 items-center justify-center text-slate-400" aria-hidden="true">↻</span>`,
  карточка `bg-white/70 border-dashed`. Никаких `disabled`-чекбоксов. Тап по карточке
  открывает редактор. Для скринридера строка начинается со скрытого текста
  «Повтор, отметить можно <дата ближайшего срока>». Под названием — подпись
  `text-xs text-slate-400` «Ближайший срок: 16 сентября».
- **Удаление** — только в редакторе, свайпов нет (случайные жесты на телефоне).

## Редактор задачи (`TaskEditor`)

Полноэкранный на телефоне (не модалка): отдельный маршрут `#/task/new` и `#/task/:id`,
чтобы кнопка «Назад» Android закрывала редактор, а не приложение.

Шапка редактора: «Отмена» (текстовая кнопка слева) — «Новая задача» / «Задача» —
«Сохранить» (справа, `font-semibold text-blue-600`, неактивна при пустом названии).

Поля сверху вниз:

1. **Название** — `textarea` в 1–3 строки, `text-lg`, автофокус только для новой задачи.
2. **Заметка** — `textarea` 3 строки, `placeholder="Заметка"`, `text-sm`.
3. **Список** — ряд чипсов `ListChips` (те же, что на экране «Задачи») + чип «Без списка».
   Без выпадающего списка: 2–6 списков помещаются в строку.
4. **Дата** — строка-поле `<input type="date">` (нативный календарь Android) плюс над ним
   ряд быстрых кнопок: «Сегодня», «Завтра», «Через неделю», «Без даты».
   Кнопки `h-10 rounded-lg border px-3 text-sm`, активная — `bg-slate-900 text-white`.
5. **Время** — `<input type="time">`, появляется только если задана дата;
   рядом кнопка «Убрать время» (`text-slate-500`), когда время задано.
6. **Повтор** — сегментированный выбор из четырёх: «Нет», «Дни», «Недели», «Месяц».
   Под ним раскрывается только нужный уточняющий блок:
   - «Дни»: «каждые [±  1  ±] дн.» — `stepper` с кнопками 44×44 и числовым полем
     `inputMode="numeric"` (без `type=number` — стрелки на десктопе мешают);
   - «Недели»: семь квадратных кнопок-переключателей
     `h-11 w-11 rounded-full border text-sm`, подписи из `WEEKDAY_LABELS`,
     `aria-pressed`, выбранный — `bg-blue-600 text-white border-blue-600`.
     Если не выбран ни один день — подставляется день недели от `dueDate`;
   - «Месяц»: «каждое [число] число», `inputMode="numeric"`, 1–31, подсказка
     `text-xs text-slate-500` «31 число в коротком месяце переносится на последний день».
7. **Приоритет** — четыре чипса в ряд: «Нет», «!1 Низкий», «!2 Средний», «!3 Высокий»,
   каждый с точкой `PRIORITY_DOT`. `role="radiogroup"`, высота 44.
8. **Удалить задачу** — внизу, отдельно от остальных полей, `w-full h-12 rounded-xl
   border border-rose-200 text-rose-600`. По тапу — подтверждение в нижнем листе
   («Удалить задачу? Отменить будет нельзя» / «Отмена» / «Удалить»).

Ошибка сохранения: строка `bg-rose-50 text-rose-700` над шапкой полей, поля не очищаются,
кнопка «Сохранить» снова активна.

Для повторяющейся задачи с уже перенесённым сроком показывается строка
`text-xs text-slate-500` «Последняя отметка: 15 сентября, 20:14» (`lastCompletedAt`).

## Экраны каркаса

### `AuthScreen` (вход)

Центрированная карточка `max-w-sm`, без нижней навигации.
Шаг 1: заголовок «Органайзер», подпись «Вход только для владельца», поле
`type="email" inputMode="email" autoComplete="email"`, кнопка «Получить код»
(`h-12 w-full rounded-xl bg-blue-600 text-white font-medium`).
Шаг 2: текст «Код отправлен на <адрес>», поле кода
`inputMode="numeric" autoComplete="one-time-code" maxLength={6}`
с крупным моноширинным шрифтом `text-2xl tracking-[0.4em] text-center`,
кнопка «Войти», ниже текстовые кнопки «Отправить код ещё раз» (с таймером 60 с)
и «Изменить адрес» (возврат к шагу 1 без потери введённого адреса).

| Состояние | Что видно |
|---|---|
| Отправка | Кнопка с текстом «Отправляем…», `disabled`, поле заблокировано |
| Неверный код | `text-rose-600` «Код неверный или истёк. Запросите новый», код выделен, поле не очищено |
| Нет пользователя | «Вход доступен только владельцу» — без намёков на регистрацию (AC4) |
| Нет сети | «Нет связи с сервером. Проверьте интернет и попробуйте снова» + «Повторить» |

### `SupabaseMissingScreen` («Supabase не настроен», AC2)

Показывается вместо всего приложения, если нет `VITE_SUPABASE_URL` /
`VITE_SUPABASE_PUBLISHABLE_KEY`. Иконка-предупреждение, заголовок «Supabase не настроен»,
текст «Создайте файл `.env` по образцу `.env.example` и перезапустите `npm run dev`»,
блок `<pre class="overflow-x-auto rounded-lg bg-slate-900 p-3 text-xs text-slate-100">`
с двумя строками переменных и списком недостающих (`text-rose-300`).
Ссылка «Подробнее — в README».

### Заглушки вкладок (`StubScreen`)

Одна компонента с параметрами `title`, `stage`, `description`.
Иконка модуля `h-12 w-12 text-slate-300`, заголовок, чип
`rounded-full bg-slate-200 px-3 py-1 text-xs text-slate-600` «Этап 3», одна строка
о том, что появится. Никаких неработающих кнопок.

## Общие состояния

| Состояние | Компонент | Вид |
|---|---|---|
| Загрузка списка | `SkeletonList` | 3 блока `h-14 rounded-xl bg-slate-200 animate-pulse`, `aria-busy="true"` |
| Загрузка сессии | `SplashScreen` | Логотип + «Загрузка…» по центру, без мигания входа |
| Пусто | `EmptyState` | Иконка `h-10 w-10 text-slate-300`, заголовок `text-sm font-medium text-slate-600`, подсказка `text-xs text-slate-500`, опциональная кнопка |
| Ошибка | `ErrorState` | `rounded-xl border border-rose-200 bg-rose-50 p-4`, понятный текст + кнопка «Повторить» (`h-11`) |
| Оффлайн | `OfflineBanner` | Полоса под шапкой: `bg-amber-100 text-amber-900 text-xs px-4 py-2` «Нет сети. Показаны последние загруженные данные», `role="status"` |

Правила:
- Текст ошибки — человеческий, без кодов: «Не удалось сохранить задачу. Попробуйте ещё раз».
  Технические детали Supabase — только в `console.error`.
- Оффлайн (`navigator.onLine === false`) блокирует действия записи: кнопки сохранения
  показывают подсказку «Нет сети» вместо тихого сбоя (допущение 8 спеки).
- Успешные действия без модалок. Удаление задачи → тост
  `fixed bottom-[calc(5rem+env(safe-area-inset-bottom))] mx-auto rounded-full bg-slate-900
  px-4 py-2 text-sm text-white`, `role="status"`, 4 секунды.

## Доступность и удобство

- Все интерактивные элементы ≥ 44×44 CSS-px (≈ 48dp при типичном DPR Android);
  для мелких иконок — прозрачный паддинг до нужного размера, не увеличение самой иконки.
- Основной текст `text-[15px]` / `text-base`; ничего меньше `text-xs` (12px).
  Поля ввода — `text-base` (16px), иначе Safari/Chrome зумят страницу при фокусе.
- Контраст: `text-slate-900` на `bg-slate-50` и `text-slate-600` на белом проходят AA.
  `text-slate-400` — только для декоративных и продублированных подписей.
  `bg-blue-600` + белый текст — AA для кнопок.
- Крупный системный шрифт: все высоты — `min-h-*` вместо фиксированных `h-*` там, где
  внутри текст (заголовки разделов, чипсы списков); карточка задачи переносит подписи
  (`flex-wrap`); нижняя навигация при `text-[11px]` не ломается, при переполнении подпись
  обрезается `truncate`, иконка остаётся.
- Одна рука: быстрый ввод продублирован — поле вверху для набора, но фокус ставится
  кнопкой «＋» в нижней трети; кнопки «Сохранить»/«Удалить» в редакторе — в зоне большого
  пальца (шапка-сохранение дублируется нижней кнопкой `sticky bottom-0` в редакторе).
  Все разрушающие подтверждения — в нижнем листе, а не в центре экрана.
- Иконки без текста обязаны иметь `aria-label`; декоративные — `aria-hidden="true"`.
- Фокус с клавиатуры: единый класс
  `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-blue-600`,
  `outline-none` без замены запрещён. В нижних листах — ловушка фокуса и закрытие по Esc,
  возврат фокуса на вызвавшую кнопку.
- Порядок DOM = визуальный порядок; заголовки `h1` (шапка) → `h2` (разделы) без пропусков.

## Палитра и типографика (Tailwind, светлая тема)

| Роль | Класс |
|---|---|
| Фон экрана | `bg-slate-50` |
| Фон карточек, шапки, панели | `bg-white` |
| Граница | `border-slate-200` (карточки), `border-slate-300` (поля) |
| Основной текст | `text-slate-900` |
| Вторичный текст | `text-slate-600` |
| Третичный/подписи | `text-slate-500` |
| Отключённое/декор | `text-slate-400` |
| Акцент, активная вкладка, ссылки | `text-blue-600` / `bg-blue-600` |
| Опасность, просрочено | `text-rose-600` / `bg-rose-50` / `border-rose-200` |
| Предупреждение, оффлайн | `bg-amber-100 text-amber-900` |

Типографика: `h1` — `text-lg font-semibold`; `h2` — `text-sm font-semibold text-slate-600`;
название задачи — `text-[15px] leading-snug`; подписи — `text-xs`; поля ввода — `text-base`.
Скругления: карточки и поля `rounded-xl`, чипсы `rounded-full`, листы `rounded-t-2xl`.
Тени: только `shadow-sm` у активного сегмента и нижнего листа — `shadow-lg`.

Приоритеты и цвета списков берутся из существующего `src/lib/labels.ts`
(`PRIORITY_DOT`, `LIST_COLORS`, `LIST_COLOR_KEYS`, `WEEKDAY_LABELS`) — новых токенов не вводим.
Правило: приоритет — всегда точка + `sr-only` текст, никогда не заливка всей карточки
(иначе конфликтует с цветом списка). Цвет списка — только чип и точка в фильтрах.
Цвет никогда не единственный носитель смысла: просрочка = цвет + слово «Вчера»,
активная вкладка = цвет + `aria-current`.

## Что осознанно НЕ делаем

- Тёмная тема — вынесена в бэклог спекой; сейчас один набор токенов.
- Свайп-жесты по карточке (выполнить/удалить) — случайные срабатывания на телефоне, нужен undo-стек.
- Перетаскивание задач между днями — в кандидатах бэклога.
- Поиск и фильтр по приоритету — не в критериях приёмки.
- Отдельный экран «Настройки» — выход из аккаунта живёт кнопкой в шапке.
- Анимации переходов между экранами — не влияют на приёмку, добавляют вес бандла.
- Кастомный date/time picker — нативные `input[type=date|time]` на Android лучше и бесплатны.
- Календарь-месяц — спека фиксирует ровно 7 дней.
- Снятие отметки у повторяющейся задачи — запрещено моделью данных (допущение 3).
- Виджет и APK-упаковка — бэклог.

## Решения дизайнера (спорные места)

1. **Стартовая вкладка — «Сегодня»**, а не «Задачи»: основной ежедневный сценарий.
2. **Редактор — отдельный маршрут, не модалка**: аппаратная «Назад» на Android должна
   закрывать редактор. Модалка в HashRouter это ломает.
3. **Виртуальное вхождение повтора — иконка ↻ вместо disabled-чекбокса**: отключённая
   кнопка выглядит как баг. Пунктирная рамка + подпись «Ближайший срок» объясняют статус.
4. **Быстрый ввод только на «Сегодня»**, на «Задачах» его нет: там уже два ряда управления,
   третий убивает список. Добавление с «Задач» — через FAB? Нет: кнопка «＋» в шапке экрана.
5. **Управление списками — нижний лист, а не отдельный экран**: операций мало, экран избыточен.
6. **Задачи без даты** показываются группой «Без даты» в конце вкладки «Все» — иначе
   их не видно вообще (допущение 4 спеки оставляет это на усмотрение).
7. **Подсказка по синтаксису быстрого ввода спрятана** за «?» — новичок здесь один
   и он же автор правил.
8. **«Выполнено сегодня» сворачивается при >3 задач** — раздел не должен вытеснять активные.
9. **Удаление задачи — только из редактора**, без быстрого доступа: два касания до
   разрушающего действия — приемлемая цена.
10. **Тост с отменой у удаления не делаем** (нет undo в слое данных) — вместо него
    подтверждение до действия.
