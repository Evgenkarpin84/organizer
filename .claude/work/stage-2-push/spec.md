# Спецификация: этап 2 — push-напоминания

Статус: критерии приёмки заморожены 23.09.2026. Всё новое сверх них — в `BACKLOG.md`.

## 1. Цель и рамки

Цель: напоминание о задаче приходит push-уведомлением на Android, даже когда компьютер выключен. Рассылка живёт целиком в Supabase: Edge Function на Deno отправляет Web Push по VAPID, `pg_cron` через `pg_net` вызывает её раз в минуту.

Входит:
- фронтенд: запрос разрешения на уведомления, подписка через service worker, хранение подписки в таблице `push_subscriptions`, выбор времени напоминания в редакторе задачи, отметка напоминания в карточке задачи, экран настроек уведомлений;
- обработчики `push` и `notificationclick` в service worker (сейчас SW генерируется `vite-plugin-pwa` в режиме `generateSW`, своих обработчиков нет);
- чистые функции расчёта времени напоминания и отбора задач/подписок к отправке, с тестами;
- миграция `supabase/migrations/0002_push_reminders.sql` и Edge Function `supabase/functions/send-reminders/` — как файлы в репозитории;
- документация настройки в `README.md`, переменная `VITE_VAPID_PUBLIC_KEY` в `.env.example`.

Не входит:
- **применение миграции и деплой Edge Function в реальный проект Supabase** — только файлы в репозитории, применение делает пользователь отдельным шагом после подтверждения;
- напоминания без срока (задача без `due_date` напоминаний не получает);
- несколько напоминаний на одну задачу, «отложить на 10 минут» из уведомления, действия-кнопки в уведомлении;
- напоминания о виртуальных вхождениях повтора (только ближайший реальный срок);
- звук/вибрация по расписанию, тихие часы, ежедневная сводка дня;
- напоминания по почте, новостям, привычкам (этапы 3–5);
- изменения в схеме задач, кроме двух колонок учёта отправки.

Отступление от шаблона: критериев 12, а не 7. Этап неделим — фронтенд без сервера и сервер без фронтенда не проверяются, — а форма списка повторяет спеку этапов 0–1 с пометками способа проверки.

## 2. Критерии приёмки

Проверка: `А` — автоматически (сборка, типы, тесты, линтер, поиск по файлам), `Р` — вручную в браузере на ПК, `Б` — только на живом проекте (применённая миграция + задеплоенная функция + телефон).

- AC1 (А). `npm run build`, `npm run typecheck`, `npm run lint`, `npm test` проходят без ошибок. Тесты не обращаются к сети, базе и браузерным push-API: в тестовых файлах нет `fetch`, `PushManager`, `serviceWorker` и обращений к Supabase.
- AC2 (А). `src/lib/reminders.ts` — чистые функции с тестами: `computeRemindAt` даёт верный момент для смещений «в момент срока» (0), «за 10 минут» (10), «за час» (60), «за день» (1440) и произвольного смещения; у задачи со сроком без времени за момент срока берётся 09:00 местного времени; без `dueDate` результат `null`; `offsetFromRemindAt` возвращает то же смещение, из которого посчитан `remind_at` (обратимость).
- AC3 (А). Отметка выполнения повторяющейся задачи пересчитывает напоминание: при переносе срока `remind_at` считается от нового срока с тем же смещением и уходит в тот же `update`, что и новый `due_date`. Покрыто тестом на чистую функцию пересчёта и тестом на обработчик отметки.
- AC4 (А). В редакторе задачи есть блок «Напоминание» с вариантами: «Нет», «В момент срока», «За 10 минут», «За час», «За день», «Своё время» (выбор даты и времени). Блок недоступен, пока не задана дата срока. Выбранное напоминание подписано датой и временем; если момент уже прошёл — видно предупреждение. В карточке задачи отметка напоминания (иконка и подпись смещения) показывается тогда и только тогда, когда `remindAt` заполнен.
- AC5 (А). Экран «Уведомления» открывается за один тап из шапки приложения и показывает ровно одно из четырёх состояний: «не поддерживается браузером», «разрешение не запрошено» (кнопка «Включить уведомления»), «запрещено в браузере» (текст, как включить в настройках сайта, кнопка включения недоступна), «включено на этом устройстве» (кнопка «Отключить на этом устройстве» и кнопка локальной проверки уведомления). Все четыре состояния покрыты тестами компонента с подставленным состоянием.
- AC6 (А). Собранный `dist` содержит `push-sw.js` с обработчиками `push` и `notificationclick`, подключённый к сгенерированному `sw.js` через `importScripts`; `registerType: 'autoUpdate'` сохранён. Пути и scope остаются относительными — приложение работает из подкаталога `/organizer/`, уведомление открывает `./#/task/<id>` относительно scope регистрации.
- AC7 (А). Миграция `supabase/migrations/0002_push_reminders.sql` создаёт таблицу `push_subscriptions` с `user_id`, уникальным `endpoint`, ключами `p256dh` и `auth`, включает RLS и заводит четыре политики с условием `user_id = auth.uid()`; добавляет в `tasks` колонки `remind_sent_at` и `remind_sent_for` и частичный индекс под выборку напоминаний; включает `pg_cron` и `pg_net` и содержит расписание вызова функции раз в минуту. Новых колонок под время напоминания нет — используется существующая `tasks.remind_at`. Скрипт идемпотентен: повторный запуск не падает.
- AC8 (А). Чистый модуль Edge Function покрыт тестами: `selectDueReminders` берёт задачи с `remind_at <= now`, не старше окна доставки, с пустым `completed_at` и без совпадения `remind_sent_for = remind_at`, и не берёт остальные; `shouldDropSubscription` истинна только для статусов 404 и 410; `buildPushPayload` содержит `taskId`, заголовок задачи, `tag` вида `task-<id>` и относительный `url`.
- AC9 (А). `supabase/functions/send-reminders/index.ts`: без совпадающего секрета в заголовке отвечает 401 и ничего не отправляет; `service_role`-ключ и приватный VAPID-ключ берутся только из переменных окружения функции. Поиск по репозиторию не находит ни приватного VAPID-ключа, ни `service_role`-ключа; во фронтенд попадает только `VITE_VAPID_PUBLIC_KEY`.
- AC10 (Б). На Android в установленном PWA: после включения уведомлений задача с напоминанием присылает push с названием задачи не позже чем через 2 минуты после времени напоминания при выключенном ПК; тап по уведомлению открывает карточку именно этой задачи.
- AC11 (Б). Одно напоминание не приходит дважды: после отправки у задачи заполнены `remind_sent_at` и `remind_sent_for = remind_at`, повторный вызов функции ту же задачу не берёт. Подписка, на которую пришёл 404 или 410, удаляется из `push_subscriptions`, остальные подписки пользователя продолжают получать уведомления.
- AC12 (А). `README.md` содержит раздел про push: генерация пары VAPID, какие секреты и где задаются (`VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, `REMINDERS_CRON_SECRET` — в секретах Edge Function; `VITE_VAPID_PUBLIC_KEY` — в `.env`), команда деплоя функции, применение миграции `0002`, включение расписания и как его отключить. В `.env.example` есть `VITE_VAPID_PUBLIC_KEY` с пустым значением. Без этой переменной приложение работает, а экран «Уведомления» показывает состояние «push не настроен».

## 3. Модель данных

`push_subscriptions`:
- `id uuid pk default gen_random_uuid()`
- `user_id uuid not null default auth.uid() references auth.users (id) on delete cascade`
- `endpoint text not null unique`
- `p256dh text not null`, `auth text not null` — ключи из `PushSubscription.toJSON().keys`
- `user_agent text null` — чтобы в настройках различать устройства
- `created_at timestamptz not null default now()`
- `last_seen_at timestamptz not null default now()` — обновляется при каждом заходе в приложение
- индекс `push_subscriptions_user_idx (user_id)`
- RLS включена, политики `select`/`insert`/`update`/`delete` с `user_id = auth.uid()`. Edge Function работает под `service_role` и RLS обходит.

`tasks` — две новые колонки:
- `remind_sent_at timestamptz null` — когда напоминание отправлено;
- `remind_sent_for timestamptz null` — значение `remind_at`, для которого отправлено. Ключ защиты от повторов.
- частичный индекс `tasks_reminders_idx on tasks (remind_at) where remind_at is not null and completed_at is null`.

Существующее поле `tasks.remind_at timestamptz` остаётся единственным местом хранения времени напоминания. Смещение («за 10 минут» и т. д.) отдельной колонкой не хранится, а выводится из разницы между сроком и `remind_at`.

Часовой пояс — как в этапе 1: `due_date` и `due_time` хранятся без зоны и трактуются в поясе устройства; `remind_at` — `timestamptz`, вычисляется на клиенте из локальных даты и времени и уходит в базу как момент времени (`Date.toISOString()`). Сервер сравнивает только `remind_at` с `now()` и про пояс ничего не знает.

## 4. Правила вычисления времени напоминания

Всё считает `src/lib/reminders.ts` чистыми функциями.

1. Момент срока: `due_date` плюс `due_time`; если времени нет — 09:00 местного времени.
2. Пресеты смещения в минутах: 0 («в момент срока»), 10 («за 10 минут»), 60 («за час»), 1440 («за день»).
3. «Своё время»: пользователь выбирает дату и время, смещение считается как разница между моментом срока и выбранным моментом в минутах (может быть отрицательным — напоминание после срока), диапазон ограничен ±30 днями.
4. `remind_at = момент срока − смещение`, приводится к ISO-строке с зоной.
5. Нет даты срока или выбрано «Нет» — `remind_at = null`.
6. Смена даты, времени или смещения в редакторе пересчитывает `remind_at` при сохранении; отдельного «пересохранения» напоминания не требуется.
7. Если вычисленный `remind_at` уже в прошлом, задача сохраняется как есть, а в редакторе видно предупреждение. Отправит сервер или нет, решает окно доставки (раздел 6).

В черновике задачи (`TaskDraft`) появляется одно поле — `remindOffsetMinutes: number | null`. В строку базы уходит уже посчитанный `remind_at`.

## 5. Повторяющиеся задачи

- Напоминание относится только к ближайшему реальному сроку. Виртуальные вхождения в «Предстоящих» уведомлений не дают.
- При отметке выполнения (обработчик `toggleTask`) для повторяющейся задачи в одном `update` уходят: новый `due_date`, `last_completed_at` и пересчитанный `remind_at` — от нового срока с прежним смещением.
- Смещение берётся из текущей пары «срок + `remind_at`». Если `remind_at` пуст, он таким и остаётся: молча включать напоминания нельзя.
- `completed_at` у повторяющейся задачи остаётся пустым, поэтому она снова попадает в выборку напоминаний — уже с новым `remind_at`, а значит и с новым ключом защиты от повторов (`remind_sent_for` не совпадает).

## 6. Устройство Edge Function

Каталог `supabase/functions/send-reminders/`:
- `index.ts` — точка входа для Deno (HTTP-обработчик, Supabase-клиент под `service_role`, отправка push);
- `reminders.ts` — чистая логика без Deno- и сетевых API;
- `reminders.test.ts` — тесты чистой логики, запускаются обычным `npm test`;
- `deno.json` — фиксация версий зависимостей функции.

Чистые функции в `reminders.ts`:
- `selectDueReminders(tasks, nowMs, options)` — отбор и сортировка задач к отправке;
- `shouldDropSubscription(status)` — `true` только для 404 и 410;
- `buildPushPayload(task)` — `{ taskId, title, body, tag: 'task-<id>', url: './#/task/<id>' }`;
- `sentPatch(task, nowIso)` — патч `{ remind_sent_at, remind_sent_for }`.

Работа `index.ts`:
1. Принимает только `POST`. Сверяет заголовок `x-cron-secret` с секретом `REMINDERS_CRON_SECRET`; не совпало или пусто — 401. Функция деплоится с `--no-verify-jwt`, доступ закрывает этот секрет.
2. Читает `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` (подставляются платформой), создаёт клиент без сохранения сессии.
3. Выбирает кандидатов: `remind_at is not null and completed_at is null and remind_at <= now()`, лимит 100, сортировка по `remind_at`.
4. Фильтрует `selectDueReminders`: окно доставки 15 минут. Задачи с `remind_at` старше окна помечаются отправленными без отправки — просроченный будильник не звонит.
5. Грузит подписки нужных пользователей одним запросом и раскладывает по `user_id`.
6. Шлёт каждой подписке зашифрованный payload с VAPID (`VAPID_PRIVATE_KEY`, публичный ключ, `VAPID_SUBJECT`).
7. Статус 404 или 410 — подписка удаляется по `endpoint`. Другая ошибка — пишется в лог, подписка остаётся.
8. Задача помечается отправленной (`remind_sent_at = now()`, `remind_sent_for = remind_at`), если хотя бы одна подписка приняла push, либо если у пользователя не осталось живых подписок — иначе задача крутилась бы в выборке каждую минуту.
9. Отвечает JSON-сводкой `{ checked, sent, failed, removed, skipped }`. Ошибка одной задачи не срывает обработку остальных.

## 7. Что настраивается в Supabase (после подтверждения, вне этой задачи)

1. Применить `supabase/migrations/0002_push_reminders.sql` в SQL Editor — таблица, колонки, индекс, RLS.
2. Сгенерировать пару VAPID: `npm run vapid` (скрипт на `node:crypto`, без зависимостей). Публичный ключ — в `.env` как `VITE_VAPID_PUBLIC_KEY`, приватный — только в секреты функции.
3. Задать секреты Edge Function: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (`mailto:` владельца), `REMINDERS_CRON_SECRET` (случайная строка).
4. Задеплоить функцию: `supabase functions deploy send-reminders --no-verify-jwt`.
5. Включить расписание: в конце миграции есть отдельная секция с `create extension pg_cron`, `create extension pg_net` и `cron.schedule('send-reminders', '* * * * *', ...)`, где `__PROJECT_REF__` и `__CRON_SECRET__` подставляются вручную перед запуском. Рядом закомментирован `cron.unschedule('send-reminders')` для отключения.
6. Пересобрать и опубликовать фронтенд (`npm run deploy`), чтобы публичный VAPID-ключ попал в бандл.
7. На телефоне открыть приложение → «Уведомления» → «Включить уведомления».

## 8. Стек и зависимости

Фронтенд — без новых npm-пакетов: Web Push API и `ServiceWorkerRegistration.pushManager` есть в браузере, `vite-plugin-pwa` уже подключён. Режим `generateSW` сохраняется, свой код подключается через `workbox.importScripts: ['push-sw.js']`, сам файл лежит в `public/push-sw.js` (обычный скрипт SW, без сборки).

Edge Function — Deno, зависимости объявлены в `deno.json` функции и в `package.json` не попадают:
- `jsr:@negrel/webpush` — VAPID и шифрование payload по `aes128gcm` (в Deno работает на WebCrypto, в отличие от npm-пакета `web-push`);
- `jsr:@supabase/supabase-js` — клиент под `service_role`.

Тесты чистой логики функции гоняет существующий Vitest: `vite.config.ts` получает в `test.include` шаблон `supabase/functions/**/*.test.ts`, `tsconfig.json` — явные пути `supabase/functions/send-reminders/reminders.ts` и `reminders.test.ts` (только они, чтобы Deno-специфичный `index.ts` не ломал `tsc`), `eslint.config.js` — исключение для `supabase/functions/**/index.ts`.

Новая переменная окружения: `VITE_VAPID_PUBLIC_KEY`. Секреты (`VAPID_PRIVATE_KEY`, `REMINDERS_CRON_SECRET`, `service_role`) в репозиторий не попадают никогда.

8. Пересчёт напоминания при отметке повторяющейся задачи в `DataProvider` и тест на это.
9. `scripts/generate-vapid.mjs`, npm-скрипт `vapid`, `.env.example`, раздел в `README.md`, актуализация `BACKLOG.md`.

Чистые функции под тестами: расчёт `remind_at` по смещению, обратное получение смещения, пересчёт при переносе срока, отбор задач к отправке, решение об удалении подписки, сборка payload, разбор base64url-ключа VAPID.

## 11. Принятые допущения

1. Напоминание требует даты срока. Задача без даты напоминаний не получает.
2. У задачи одно напоминание. Смещение не хранится отдельной колонкой, а выводится из `remind_at` и срока — поэтому «своё время» тоже превращается в смещение и переживает перенос срока повтора.
3. Срок без времени для напоминаний считается назначенным на 09:00 местного времени.
4. Окно доставки — 15 минут: напоминание, опоздавшее сильнее (сбой cron, задача с прошлым временем), помечается отправленным и не приходит. Иначе после простоя посыпалась бы пачка старых уведомлений.
5. Доступ к Edge Function закрыт своим секретом в заголовке, а не JWT: вызов идёт из `pg_cron`, у которого сессии пользователя нет.
6. Секции `pg_cron`/`pg_net` в миграции идут с placeholders `__PROJECT_REF__` и `__CRON_SECRET__` — URL проекта и секрет в репозиторий не попадают.
7. Подписка привязана к устройству: каждый браузер даёт свой `endpoint`, уведомление уходит на все живые подписки владельца.
8. Состояний на экране настроек четыре, а не три: добавлено «не поддерживается браузером» — на iOS и в части десктопных браузеров Push API отсутствует, без этого состояния экран выглядел бы сломанным.
9. Отключение уведомлений на устройстве удаляет подписку из базы и снимает её в браузере, но системное разрешение не отзывает — браузер такого API не даёт.
10. Web Push из Deno делается через `jsr:@negrel/webpush`: писать шифрование `aes128gcm` и VAPID-JWT вручную дороже и рискованнее, а npm-пакет `web-push` в Deno-рантайме Supabase не работает из-за зависимостей Node.
11. Экран уведомлений живёт по маршруту `/settings` и открывается шестерёнкой в шапке: нижняя навигация зафиксирована пятью вкладками в AC6 этапов 0–1.
12. Тестовое уведомление на экране настроек показывается локально через `registration.showNotification`, без обращения к серверу.

## 12. Следующие итерации

- Перенос напоминания из самого уведомления («отложить на 10 минут») — нужны `actions` в уведомлении и своя точка входа на сервере.
- Несколько напоминаний на одну задачу (отдельная таблица `reminders`).
- Тихие часы и утренняя сводка дня одним уведомлением.
- Экран истории отправленных напоминаний и статуса подписок по устройствам.

## 13. Кандидаты в бэклог

- Напоминания о письмах (этап 3) и дайджесте новостей (этап 4) через тот же механизм.
- Периодическая проверка живости подписок и авто-переподписка при `pushsubscriptionchange`.
- Напоминания без срока: «напомнить через 3 часа» от текущего момента.
- Уведомления с картинкой и прогрессом чеклиста (этап 5).
- Своё SMTP и дублирование важных напоминаний письмом.
- Упаковка PWA в APK, чтобы уведомления не зависели от Chrome.
