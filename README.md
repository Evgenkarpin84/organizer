# Органайзер

Персональный органайзер-ассистент: PWA, которое ставится на Android с рабочего стола. Пять модулей: задачи с планировщиком, push-напоминания, почта по IMAP, новости по лентам, привычки и чеклисты. Архитектура и план этапов — в [CLAUDE.md](CLAUDE.md), спецификации этапов — в `.claude/work/`.

Включение готовых модулей (миграции, напоминания, сбор почты и новостей) расписано по шагам в `ЗАПУСК.md` — там весь порядок целиком, а разделы ниже описывают каждый модуль подробно.

## Быстрый старт

```bash
npm install
cp .env.example .env   # и заполнить значения
npm run icons          # иконки PWA, достаточно один раз
npm run dev
```

## Переменные окружения

| Переменная | Где взять |
|---|---|
| `VITE_SUPABASE_URL` | Supabase → Project Settings → Data API → Project URL |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Supabase → Project Settings → API Keys → publishable (`sb_publishable_…`). Подходит и старый `anon`-ключ |

Без этих переменных приложение не падает, а показывает экран «Supabase не настроен». Ключ `service_role` во фронтенде не используется никогда, `.env` в `.gitignore`.

## Настройка Supabase

1. **Схема.** Выполнить `supabase/migrations/0001_init.sql` в SQL Editor проекта. Скрипт создаёт таблицы `lists` и `tasks`, индексы, триггер `updated_at` и политики RLS: каждая строка видна только своему владельцу.
2. **Пользователь-владелец.** Authentication → Users → Add user → Create new user: адрес почты, пароль (с ним и будете входить), галочка «Auto Confirm User».
3. **Закрыть регистрацию.** Authentication → Sign In / Providers → Email → выключить «Allow new users to sign up».
4. **Вход по паролю.** Приложение использует `signInWithPassword`, письма Supabase не задействованы. Причина: на бесплатном тарифе шаблоны писем нельзя редактировать без своего SMTP («Set up custom SMTP to edit templates»), а у встроенной почты жёсткий лимит на письма. Вход по коду вернётся, когда будет подключён SMTP — пункт есть в `BACKLOG.md`. Сменить пароль: Authentication → Users → пользователь → Reset password. Ссылка на Android открывается в браузере, а не в установленном приложении, поэтому вход сделан по коду.

## Push-напоминания

Напоминания рассылает Supabase, поэтому они приходят и при выключенном компьютере: `pg_cron` раз в минуту дёргает Edge Function `send-reminders`, та отправляет Web Push по VAPID.

1. **Ключи VAPID.** Выполнить `npm run vapid`. Публичный ключ положить в `.env` как `VITE_VAPID_PUBLIC_KEY`, приватный — только в секреты функции, в репозиторий он не попадает.
2. **Схема.** Выполнить `supabase/migrations/0002_push_reminders.sql` в SQL Editor: таблица `push_subscriptions` с RLS, колонки `remind_sent_at` и `remind_sent_for`, индекс. Секция с расписанием в конце файла закомментирована — она запускается отдельно на шаге 5.
3. **Секреты функции.** В настройках Edge Functions задать `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (вида `mailto:почта@владельца`) и `REMINDERS_CRON_SECRET` (случайная строка).
4. **Деплой функции:**
   ```bash
   npx supabase functions deploy send-reminders --no-verify-jwt
   ```
   Проверка JWT отключена намеренно: вызов идёт из `pg_cron`, доступ закрывает секрет в заголовке `x-cron-secret`.
5. **Расписание.** Раскомментировать секцию в конце миграции, подставив идентификатор проекта и значение `REMINDERS_CRON_SECRET`, и выполнить её. Отключается командой `select cron.unschedule('send-reminders');`, журнал запусков — в `cron.job_run_details`.
6. **Сборка и публикация:** `npm run deploy` — публичный ключ попадёт в бандл.
7. **На телефоне:** открыть приложение → шестерёнка в шапке → «Включить уведомления».

Без `VITE_VAPID_PUBLIC_KEY` приложение работает как обычно, а экран «Уведомления» показывает состояние «Push не настроен».

## Почта

Письма забирает скрипт на компьютере: подключается к ящикам по IMAP и складывает их в Supabase, а приложение показывает их на вкладке «Почта». Пока компьютер выключен, новые письма не появляются — это осознанное ограничение, в отличие от напоминаний из этапа 2.

### 1. Пароли приложений

Основной пароль от почты не подходит и не нужен.

- **Mail.ru** (bk.ru, inbox.ru, list.ru тоже): [id.mail.ru](https://id.mail.ru) → «Безопасность» → «Пароли для внешних приложений» → создать пароль, скопировать.
- **Яндекс**: [id.yandex.ru](https://id.yandex.ru) → «Безопасность» → «Пароли приложений» → «Почта». Дополнительно в почте включить доступ: «Все настройки» → «Почтовые программы» → разрешить IMAP.

### 2. Переменные окружения

Заполняются в `.env`, во фронтенд не попадают (нет префикса `VITE_`):

| Переменная | Значение |
|---|---|
| `SUPABASE_URL` | адрес проекта |
| `SUPABASE_SERVICE_ROLE_KEY` | сервисный ключ: Project Settings → API Keys → secret |
| `OWNER_USER_ID` | Authentication → Users → UID владельца |
| `MAIL_n_PROVIDER` | `mailru` или `yandex` |
| `MAIL_n_EMAIL`, `MAIL_n_PASSWORD` | адрес ящика и пароль приложения |
| `MAIL_n_LABEL` | необязательно: подпись ящика в приложении |
| `MAIL_BACKFILL_DAYS`, `MAIL_MAX_PER_RUN` | пределы первого запуска: 30 дней и 200 писем |

### 3. Схема

Выполнить `supabase/migrations/0003_mail.sql` в SQL Editor: таблицы `mail_accounts` и `mail_messages`, индексы и политики RLS.

### 4. Запуск

```bash
npm run mail -- --check
```

Печатает список ящиков и ничего не отправляет в сеть — так проверяются настройки.

```bash
npm run mail -- --dry-run
```

Подключается к ящикам и говорит, сколько писем добавилось бы, ничего не записывая.

```bash
npm run mail
```

Забирает письма. Повторный запуск сразу после первого добавит 0 писем: дедупликация по `Message-ID`. Ещё есть `--account=mail1` (один ящик), `--limit=50` (не больше N писем) и `--verbose`.

### 5. Расписание Windows

Оба задания — почта каждые 30 минут и новости каждые 2 часа — заводит один скрипт, повторный запуск перезаписывает их:

```powershell
pwsh -File scripts\register-tasks.ps1
```

Задания называются «Органайзер — почта» и «Органайзер — новости» (двоеточие в имени задания Windows не допускает). Команды идут через `conhost --headless`, поэтому окно консоли не мелькает. Пропущенный из-за сна запуск выполняется при пробуждении, второй экземпляр не стартует, пока идёт первый.

Разовый запуск — `Start-ScheduledTask 'Органайзер — почта'`, удалить — `Unregister-ScheduledTask 'Органайзер — почта' -Confirm:$false`. Журнал пишется в `logs\mail.log`, папка `logs/` в `.gitignore`.

### Что хранится в базе

- Только текст письма: `text/plain` как есть, `text/html` — переведённый в текст. HTML не сохраняется нигде.
- Обычное письмо — первые 2000 символов, рассылка — 500. Обрезка помечается, полное письмо остаётся в ящике.
- Вложения не скачиваются: сохраняются признак наличия и до 10 имён файлов.
- Текстовая часть больше 256 КБ не загружается вовсе.
- Читается только папка «Входящие». Флаги в самом ящике скрипт не меняет: «прочитано» и «архив» живут внутри органайзера.

## Новости

Публикации по темам приносит скрипт на компьютере: читает ленты RSS и Atom и складывает их в Supabase, а вкладка «Новости» показывает их по темам. Как и с почтой, при выключенном ПК ленты не читаются.

### Темы и источники

Темы заданы восемью ключами: `ozon` (Ozon для продавца), `cars` (китайские автомобили), `gadgets` (смартфоны и гаджеты), `print3d` (3D-печать), `cinema` (кино и сериалы), `ai` (ИИ и технологии), `finance` (экономика и финансы), `world` (мир и политика).

Список лент — единственный файл `scripts/news/sources.json`:

```json
{
  "key": "kolesa",
  "topic": "cars",
  "title": "Kolesa.ru",
  "feedUrl": "https://www.kolesa.ru/rss",
  "enabled": true,
  "include": ["chery", "haval", "китайск"]
}
```

- `key` — уникальный ключ источника, `topic` — одна из восьми тем, `title` — название в приложении.
- `include` необязателен: если он есть, берутся только публикации, где одно из слов встречается в заголовке или описании. Так узкие темы («Ozon для продавца», «китайские автомобили») собираются из общих отраслевых лент — своих лент у них нет.
- Убрать источник: `"enabled": false` или удалить запись целиком. Добавить — дописать объект и запустить сбор.
- На каждую тему стоит держать минимум две ленты: если одна замолчит, тема не опустеет.

### Переменные окружения

Те же `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` и `OWNER_USER_ID`, что у почты, плюс необязательные `NEWS_BACKFILL_DAYS` (окно свежести, по умолчанию 7 дней) и `NEWS_MAX_PER_SOURCE` (сколько публикаций брать с ленты за запуск, по умолчанию 30).

### Схема и запуск

Выполнить `supabase/migrations/0004_news.sql` в SQL Editor, затем:

```bash
npm run news -- --check
```

Печатает источники по темам и не делает ни одного сетевого запроса.

```bash
npm run news -- --dry-run
```

Читает ленты и показывает, сколько публикаций добавилось бы, ничего не записывая. Этой командой проверяются адреса лент: если лента переехала, будет видно сразу.

```bash
npm run news
```

Забирает публикации. Ещё есть `--source=4pda`, `--topic=ai` и `--limit=10`.

### Расписание Windows

Задание «Органайзер — новости» заводит тот же `scripts\register-tasks.ps1`, что и почтовое (см. раздел «Почта»). Раз в два часа: новостям не нужна минутная свежесть. Журнал — `logs\news.log`.

Если лента на условный запрос с `ETag` отвечает `200` с пустым телом вместо `304` (так делает Oborot.ru), это считается «без изменений», а не ошибкой.

### Что хранится в базе

Только то, что отдаёт лента: заголовок (до 200 символов), ссылка, краткое описание (до 400 символов), дата, тема и источник. Полный текст статей и картинки не загружаются — статья открывается по ссылке во внешнем браузере. Отметка «прочитано» ставится в момент перехода по ссылке.

## Привычки и чеклисты

Последний модуль: внешних служб ему не нужно, всё создаётся прямо в приложении. Достаточно выполнить `supabase/migrations/0005_habits.sql` в SQL Editor.

### Привычки

Цель бывает трёх видов:

| Цель | Что считается серией | Что считается процентом |
|---|---|---|
| Каждый день | дни подряд с отметкой | отметки за последние 7 дней из 7 |
| N раз в неделю | календарные недели (пн–вс), где отметок не меньше нормы | отметки за последние 7 дней из нормы |
| По выбранным дням недели | запланированные дни подряд; незапланированные дни серию не рвут | отметки за последние 7 дней из числа запланированных |

- Незакрытый сегодняшний день серию не обнуляет: отсчёт идёт от вчера. Иначе каждое утро вы видели бы «нет серии».
- Отметить можно любой из семи дней сетки, включая прошедшие: забытый вчерашний день закрывается тапом.
- Отметка привязана к дате устройства, как срок задачи. Часовой пояс нигде не хранится.
- Серия считается по окну в 180 дней; всё, что длиннее, показывается как «180+ дней подряд».
- Архив прячет привычку с экрана «Сегодня» и из активного списка, отметки при этом сохраняются. Удаление стирает и отметки.

### Чеклисты

Шаблон проходится по пунктам: прогресс «5 из 12» виден в списке. Прохождение начинается само, первой отметкой. Кнопка **«Завершить»** запоминает дату прохождения и снимает все отметки, **«Начать заново»** просто снимает отметки. Истории прохождений на этом этапе нет: хранится только текущее состояние, дата начала и дата последнего завершения. Напоминаний о привычках тоже пока нет — механизм push из этапа 2 умеет только задачи.

Приложение опубликовано: **https://evgenkarpin84.github.io/organizer/**

Хостинг — GitHub Pages, сайт раздаётся из ветки `gh-pages`, куда попадает содержимое `dist`. Обновить сайт после правок:

```bash
npm run deploy
```

## Структура

```
src/lib        чистые функции: даты, повторения, быстрый ввод, напоминания,
               почта, новости, привычки и чеклисты
src/data       Supabase и провайдеры: задачи, почта, новости, привычки, push, сессия
src/components каркас, карточка задачи, письма и новости, строка привычки,
               чеклист, блок привычек на «Сегодня»
src/screens    экраны: Сегодня, Задачи, Почта и письмо, Новости, Привычки,
               редакторы задачи, привычки и чеклиста, вход, уведомления
scripts        сбор почты (fetch-mail.mjs), сбор новостей (fetch-news.mjs и
               news/sources.json), генератор иконок, ключи VAPID
supabase       SQL-миграции 0001–0005 и Edge Function рассылки напоминаний
```

## Быстрый ввод

Строка разбирается без обращения к модели:

- дата: `сегодня`, `завтра`, `послезавтра`, `в пятницу`, `пн`, `через 3 дня`, `через неделю`, `15.09`, `15.09.2027`;
- время: `в 18`, `в 18:30`, `18:30`;
- приоритет: `!1`, `!2`, `!3`;
- список: `#Работа` — если списка с таким именем нет, текст останется в названии;
- повтор: `каждый день`, `каждые 3 дня`, `каждый вторник`, `каждую неделю`, `каждый месяц`.

Пример: `Отчёт в пятницу в 18:00 !3 #Работа`.

## Повторяющиеся задачи

Отметка выполнения не закрывает такую задачу, а переносит срок на следующую дату по правилу — всегда строго позже сегодняшнего дня. Момент отметки хранится в `last_completed_at`, поэтому задача попадает в раздел «Выполнено сегодня». Ежемесячный повтор с 31 числом в коротком месяце переносится на последний день месяца.
