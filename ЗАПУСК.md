# Как включить готовые модули

> **Состояние на 24.09.2026:** шаги 1–4 выполнены на живом проекте — миграции применены, функция напоминаний задеплоена, расписание `pg_cron` работает, почта и новости собираются заданиями Планировщика Windows. Файл остаётся инструкцией на случай переустановки или нового проекта.

Ниже — весь путь включения по шагам, по порядку. Каждый шаг самостоятельный: можно остановиться после любого и вернуться позже.

Обозначения: **SQL Editor** — это Supabase → слева иконка `SQL Editor` → кнопка `New query`. Команды в блоках `powershell` выполняются в PowerShell из папки проекта: открой её, набери `cd C:\newIDEA`, нажми Enter.

---

## Шаг 1. Миграции базы (15 минут, без них ничего не заработает)

Файлы лежат в `supabase/migrations/`. Применяются строго по возрастанию, один за другим. Для каждого: открой файл в редакторе, скопируй всё содержимое, вставь в SQL Editor, нажми `Run`. Должно появиться `Success. No rows returned`.

- [ ] `0002_push_reminders.sql` — подписки на уведомления. **Важно:** в конце файла есть закомментированная секция про расписание (`cron.schedule`). Её не трогай, она пойдёт в шаге 2.6.
- [ ] `0003_mail.sql` — ящики и письма.
- [ ] `0004_news.sql` — источники и публикации.
- [ ] `0005_habits.sql` — привычки, отметки, чеклисты и пункты.

Проверка: Supabase → `Table Editor`. Должны появиться таблицы `push_subscriptions`, `mail_accounts`, `mail_messages`, `news_items`, `habits`, `habit_entries`, `checklists`, `checklist_items`.

После этого вкладки «Почта», «Новости» и «Привычки» в телефоне перестанут показывать ошибку загрузки. Привычки и чеклисты сразу рабочие — их можно создавать и отмечать. Почта и новости останутся пустыми, пока не заработают сборщики (шаги 3 и 4).

## Шаг 2. Push-напоминания

Самый длинный шаг: тут и ключи, и деплой функции. Если устал — отложи, остальное от него не зависит.

**2.1. Ключи VAPID.** В PowerShell:

```powershell
npm run vapid
```

Команда напечатает два ключа — публичный и приватный. Окно не закрывай, ключи нужны дальше.

**2.2. Публичный ключ в `.env`.** Открой `C:\newIDEA\.env` в Блокноте, найди строку `VITE_VAPID_PUBLIC_KEY=` и вставь публичный ключ сразу после `=`, без кавычек и пробелов. Сохрани.

**2.3. Секреты функции.** Supabase → `Edge Functions` → `Secrets` → `Add new secret`. Добавь четыре:

| Имя | Значение |
| --- | --- |
| `VAPID_PUBLIC_KEY` | публичный ключ из шага 2.1 |
| `VAPID_PRIVATE_KEY` | приватный ключ из шага 2.1 |
| `VAPID_SUBJECT` | `mailto:` и адрес владельца, например `mailto:имя@mail.ru` |
| `REMINDERS_CRON_SECRET` | любая случайная строка, например из `npm run vapid` можно взять часть, или придумай 20 символов. Её понадобится вставить в шаге 2.6 — запиши. |

Приватный ключ в `.env` и в репозиторий не попадает никогда.

**2.4. Вход в Supabase CLI.** Понадобится токен доступа: Supabase → `Account` → `Access Tokens` → `Generate new token`. Права: `Database: Read-write`, `Edge Functions: Read-write`, `Edge Function Secrets: Read-write` и чтение в разделе `Project`, всё остальное `None`, срок — самый короткий.

```powershell
npx supabase login
```

**2.5. Деплой функции.** Флаг `--use-api` собирает функцию на стороне Supabase, Docker не нужен.

```powershell
npx supabase functions deploy send-reminders --project-ref gtinstytiagmomnvgisl --no-verify-jwt --use-api
```

Проверка JWT отключена намеренно: функцию вызывает не браузер, а планировщик внутри базы, и доступ закрывает секрет в заголовке.

**2.6. Расписание.** Открой `supabase/migrations/0002_push_reminders.sql`, найди в конце закомментированную секцию с `cron.schedule`. Скопируй её в SQL Editor, убери символы комментария, подставь вместо заглушек идентификатор проекта `gtinstytiagmomnvgisl` и значение `REMINDERS_CRON_SECRET` из шага 2.3, нажми `Run`.

Проверить, что расписание живёт: `select * from cron.job;`. Журнал запусков: `select * from cron.job_run_details order by start_time desc limit 20;`. Выключить: `select cron.unschedule('send-reminders');`.

**2.7. Публикация сайта.** Публичный ключ попадает в приложение только при сборке:

```powershell
npm run deploy
```

**2.8. На телефоне.** Открой приложение, потяни страницу вниз для обновления (или закрой и открой заново), шестерёнка в шапке → «Включить уведомления» → разреши уведомления в запросе Android. Затем создай задачу на 2 минуты вперёд с напоминанием «в момент срока» и убедись, что уведомление пришло.

Если экран уведомлений пишет «Push не настроен» — значит сайт собрался без ключа: проверь `.env` и повтори 2.7.

## Шаг 3. Сбор почты

**3.1. Сервисные переменные.** В `.env` заполни:

- `SUPABASE_URL` — тот же адрес, что в `VITE_SUPABASE_URL`.
- `SUPABASE_SERVICE_ROLE_KEY` — Supabase → `Project Settings` → `API Keys` → ключ `service_role`. Он обходит все проверки доступа, поэтому живёт только в `.env` на твоём ПК.
- `OWNER_USER_ID` — Supabase → `Authentication` → `Users` → строка с адресом владельца, скопируй `UID`.

**3.2. Ящики.** Для каждого ящика заполни четвёрку `MAIL_1_*` … `MAIL_4_*`: `PROVIDER` (`mailru` или `yandex`), `EMAIL`, `PASSWORD` (пароль приложения, не основной пароль от почты), `LABEL` (как подписать ящик в приложении, например «Личная» или «Озон»). Если ящик не нужен, удали все его строки целиком: ящик с заполненным `PROVIDER`, но пустым `EMAIL` скрипт считает ошибкой.

**3.3. Проверка настроек без сети:**

```powershell
npm run mail -- --check
```

Напечатает список ящиков, которые увидел. Если ящик не в списке — значит в его строках опечатка.

**3.4. Проверка подключения без записи:**

```powershell
npm run mail -- --dry-run
```

Подключается к ящикам и говорит, сколько писем добавилось бы. Здесь видно, приняли ли сервера пароли приложений.

**3.5. Первый настоящий сбор:**

```powershell
npm run mail
```

По умолчанию забирает письма за 30 дней, не больше 200 за раз (`MAIL_BACKFILL_DAYS` и `MAIL_MAX_PER_RUN` в `.env`). Если писем за 30 дней больше, остаток подтянется следующими запусками. Одно и то же письмо дважды не сохранится: дубликаты отсекаются по `Message-ID`.

**3.6. Расписание.** Один скрипт заводит оба задания: почта каждые 30 минут, новости каждые 2 часа. Окно консоли при этом не мелькает.

```powershell
pwsh -File scripts\register-tasks.ps1
```

Разовый запуск — `Start-ScheduledTask 'Органайзер — почта'`, удалить — `Unregister-ScheduledTask 'Органайзер — почта' -Confirm:$false`. Журнал в `logs\mail.log`.

Письма автоматически не отправляются и не удаляются: приложение только читает.

## Шаг 4. Сбор новостей

Переменные из шага 3.1 нужны и здесь, отдельных ключей новостям не требуется.

**4.1. Список источников без сети:**

```powershell
npm run news -- --check
```

**4.2. Проверка лент без записи:**

```powershell
npm run news -- --dry-run
```

Здесь важно посмотреть на ошибки: из 17 лент часть может переехать или отвечать `404`. Пришли мне вывод — поправлю адреса в `scripts/news/sources.json`.

**4.3. Первый сбор:**

```powershell
npm run news
```

**4.4. Расписание.** Задание «Органайзер — новости» заводит тот же `scripts\register-tasks.ps1` из шага 3.6. Журнал в `logs\news.log`.

## Шаг 5. Что останется потом

- **Этап 3b — разбор писем моделью:** категории, приоритеты, задачи из писем и черновики ответов. Сейчас вкладка «Почта» показывает письма как есть.
- **Этап 4b — сводки новостей:** короткий пересказ вместо списка заголовков и утренний дайджест.
- Остальные идеи — в `BACKLOG.md`, там же технический долг по каждому этапу.

## Если что-то не так

- **Вкладка показывает «Не удалось загрузить»** — не применена миграция этого модуля (шаг 1) или нет сети.
- **Скрипт падает с `SUPABASE_SERVICE_ROLE_KEY`** — переменная пустая или в `.env` остался пробел после `=`.
- **`npm` не находится** — открой PowerShell заново: после установки Node.js путь подхватывается только в новых окнах.
- **Уведомления не приходят** — по порядку: `select * from cron.job_run_details order by start_time desc limit 5;` (дёргается ли функция), затем Supabase → `Edge Functions` → `send-reminders` → `Logs` (что она ответила), затем экран «Уведомления» в приложении (жива ли подписка).
