# Бэклог

Идеи на будущее. Приоритеты: P1 — скоро, P2 — потом, P3 — когда-нибудь.

## Новости

- **P2. Еженедельная подборка товаров Ozon.** Раз в неделю список популярных и интересных товаров. Идея пользователя от 11.09.2026.

## Доступ и инфраструктура

- **P1. Обновлять данные при возврате в приложение и при смене суток.** `DataProvider` загружает задачи один раз при старте, `todayISO()` считается на рендере: свёрнутое на ночь приложение утром покажет вчерашний день, а задачи, созданные скриптами на ПК (этапы 3–4), не появятся до перезапуска. Нужен перезапрос по `visibilitychange`/`online` и пересчёт текущей даты по таймеру; это же снимает пункты долга про смену суток.
- **P2. Каркас скриптов-«мозга» на ПК с журналом запусков.** В `scripts/` пока только генератор иконок, а этапам 3–5 нужен общий модуль: чтение `.env`, подключение к Supabase сервисным ключом, единый запуск по расписанию Windows и таблица `job_runs` (задание, старт, длительность, статус, ошибка). Без журнала будет невозможно понять, отработал ли ночной разбор почты или молча упал.

- **P2. Вход по коду из письма вместо пароля.** Требует своего SMTP (Mail.ru или Яндекс с паролем приложения): только тогда Supabase разрешает редактировать шаблоны писем и снимается лимит встроенной почты в пару писем в час. Пока вход по паролю.

## Надёжность данных

- **P2. Офлайн-очередь на запись.** Сейчас без сети приложение только читает кэш и блокирует сохранение, поэтому в метро или на даче задачу записать некуда. Чем больше модулей начнут писать в Supabase (почта, новости, привычки), тем дороже встраивать очередь потом — дешевле сделать её на одном модуле задач.
- **P2. Резервная копия базы в файл на ПК.** Все данные владельца живут в одном бесплатном проекте Supabase, который может быть приостановлен или потерян. Нужен скрипт, выгружающий таблицы в JSON в локальную папку по расписанию, и описание обратной заливки в README.

## Уведомления

- **P1. Авто-переподписка при смене endpoint и тихая проверка подписки при запуске.** Chrome сам меняет `endpoint` (переустановка PWA, чистка данных, ротация на стороне FCM), и после этого напоминания молча перестают приходить: подписка в базе мёртвая, а приложение об этом узнаёт только когда владелец сам зайдёт на «Уведомления». Нужен обработчик `pushsubscriptionchange` в `push-sw.js`, который перезаписывает строку в `push_subscriptions`, плюс сверка «разрешение есть, а живой подписки нет» при каждом заходе в приложение с заметной подсказкой на экране «Сегодня».
- **P2. Журнал рассылки напоминаний и строка «последняя проверка» на экране «Уведомления».** Сейчас сводка `{ checked, sent, failed, removed, skipped }` уходит только в логи Supabase, которые на бесплатном тарифе живут недолго: если уведомление не пришло, понять, отработал ли `pg_cron`, упала ли функция или не было подписки, нельзя вообще. Нужна таблица запусков (тот же `job_runs`, что и для скриптов-«мозга»), куда функция пишет сводку, и одна строка на экране «Уведомления»: когда последний раз проверяли напоминания и сколько отправили за сутки.
- **P2. Единая очередь уведомлений вместо жёсткой привязки к задачам.** `send-reminders` умеет только выбирать задачи по `remind_at`, поэтому этапы 3–5 (пришло важное письмо, готов дайджест, не отмечена привычка) будут либо копировать VAPID-шифрование и обработку 404/410 в новую функцию, либо не получат push совсем. Таблица `push_outbox` (`user_id`, `title`, `body`, `url`, `tag`, `send_after`, `sent_at`) и отправка из неё превращают любой модуль в поставщика уведомлений одной вставкой строки; чем позже, тем дороже — логику доставки придётся разносить по двум функциям.
- **P2. Утренняя сводка дня одним уведомлением.** Раз в день в заданное время приходит одно уведомление вида «Сегодня: 4 задачи, 2 со сроком до обеда» с переходом на экран «Сегодня» — это единственный способ узнать про день, не открывая приложение по привычке; расписание `pg_cron`, функция отправки и подписки для этого уже есть.
- **P3. «Отложить на 10 минут» из уведомления.** Кнопка-действие в уведомлении сдвигает `remind_at` задачи, не заставляя открывать редактор и править время вручную. Дешёвый вариант без серверной точки входа: действие открывает приложение по ссылке вида `./#/task/<id>?snooze=10`, а сдвиг делает уже сам фронтенд с живой сессией.

## Технический долг (из ревью этапа 3)

- **P2. Лишняя загрузка письма при пустом добавлении.** `UID FETCH lastUid+1:*` возвращает последнее письмо, даже когда новых нет, и его текстовая часть скачивается каждый запуск.
- **P2. Нулевой `last_uid` после пустого первого прохода** заставляет следующий запуск снова делать поиск за 30 дней.
- **P3. `MAIL_MAX_PER_RUN` применяется в точке входа**, а не в чистой функции `fetchRange`, поэтому не покрыт юнит-тестом.
- **P3. `.env.example` задаёт значения** `MAIL_n_PROVIDER`, `MAIL_BACKFILL_DAYS`, `MAIL_MAX_PER_RUN`, хотя по критерию значения должны быть пустыми.
- **P2. Расписание Windows не создаёт папку `logs/`** — первый запуск задания молча ничего не пишет; нужен `md logs` в команде.
- **P3. Группы по ящику** упорядочены по первому письму, а не по порядку ящиков, из-за чего позиция ящика прыгает.
- **P3. Строка «Кому» на экране письма** не выводится: поля `to_emails` нет ни во фронтенд-типе, ни в выборке.
- **P3. `htmlToPlainText`** не разворачивает шестнадцатеричные сущности и ломает символы выше BMP.
- **P3. Заметка задачи из письма** при пустом имени отправителя выглядит как «От: a@b.ru <a@b.ru>».
- **P2. Кнопка «Повторить» на вкладке «Почта»** подменяет список скелетоном вместо того, чтобы оставить его рабочим.
- **P3. Предзаполнение редактора задач черновиком из письма** не покрыто тестом.
- **P3. Ошибка скачивания части письма** печатается в verbose-логе без чистки от паролей.

- **P3. Откат оптимистичного обновления в `MailProvider`** опирается на значение, захваченное внутри апдейтера: надёжнее держать зеркало списка в `useRef`.
- **P3. Сводка запуска `fetch-mail`** не показывает число пропущенных дубликатов, хотя спека это обещает.
- **P3. Прямая ссылка на письмо** делает лишний однострочный запрос параллельно с первичной загрузкой списка.

## Технический долг (из ревью этапа 2)

- **P2. Дата срока в тексте уведомления.** Сейчас в `body` только время («срок в 18:00»); для напоминания «за день» непонятно, на какой день срок.
- **P2. Сведения об устройствах на экране уведомлений.** `countSubscriptions` не используется, строки «Устройство добавлено» и «Всего устройств» из дизайна не сделаны.
- **P3. `last_seen_at` обновляется только на экране настроек**, а не при каждом заходе в приложение.
- **P2. `client.navigate` в push-sw.js без try/catch:** для неконтролируемого окна вызов отклоняется и тап по уведомлению ничего не делает.
- **P3. Подсказка «уведомления выключены» в редакторе** смотрит только на разрешение браузера, без проверки наличия подписки.
- **P3. Чип «Своё время» со смещением 60** после переоткрытия задачи подсвечивается как «За час».
- **P3. Ошибка удаления подписки** оставляет экран в состоянии «включено» до следующего обновления.
- **P3. Мёртвые подписки не убираются из списка в памяти** внутри одного запуска функции.
- **P3. Нет защиты от наложения запусков cron** — два одновременных вызова теоретически дублируют уведомление (визуально спасает tag).
- **P2. `index.ts` Edge Function не покрыт ни типами, ни линтером** — единственный файл, который не проверяется автоматически.

- **P3. Счётчик `failed` в сводке функции** не различает ошибку доставки конкретной подписке и сбой обработки задачи целиком.
- **P3. Напоминание, опоздавшее больше часа**, не попадает в выборку и навсегда остаётся с пустым `remind_sent_for` — в базе выглядит как «ещё не отправлено».

## Технический долг (из ревью этапов 0–1)

- **P2. Локальное время последней отметки в редакторе.** `TaskEditorScreen` берёт дату из `lastCompletedAt.slice(0, 10)` — это UTC, после полуночи покажет «Вчера»; нужно локальное время и формат «15 сентября, 20:14».
- **P2. Ложные срабатывания парсера дат.** «3.5 кг» или «1.5 л» в быстром вводе распознаются как дата; нужна проверка контекста.
- **P3. Предлог «в» остаётся в названии**, когда дата записана как «в 18.09».
- **P2. Ловушка фокуса в нижнем листе** и возврат фокуса на вызвавшую кнопку.
- **P2. Разное поведение вкладок для отмеченных повторов:** «Все» их прячет, «Предстоящие» показывает.
- **P3. Липкое поле быстрого ввода** на экране «Сегодня» — по дизайну оно должно оставаться на месте при прокрутке.
- **P2. Пагинация задач** в `fetchTasks`: сейчас загружаются все незавершённые задачи одним запросом.
- **P3. `navigate(-1)` в редакторе** уводит из приложения при открытии по прямой ссылке — нужен запасной переход на «/».
- **P3. Позиции списков** (`position: lists.length`) дублируются после удалений.
- **P3. Смена суток при открытом приложении:** `todayISO()` вычисляется на рендере, «Сегодня» сам не переключится.
- **P3. Защита от `null` в `nextDueDateAfterCompletion`** перед записью `due_date`.
- **P3. Проверка в миграции**, что `tasks.list_id` принадлежит тому же пользователю.
